| 查询                             | 模式             | 已核对结果                             | 项目取舍                                                |

## 5. 实施顺序与试点边界

1. 完成安装、项目约束及本审查报告，先登记差异再改页面。
2. 在 component-specs.md 补齐公共组件规格，design.md 只引用、回写冲突，避免复制大表。

4. 保留预设、格式、质量、宽度、真实体积增减、逐项错误、重试、下载与清空入口。
5. 不改其他模块公共 CSS 或主题，不借试点全局推广；用户确认后再选择下一模块。

## 6. 用户验收清单

- 图片压缩标题与模块图标是否协调，上传区到结果是否留白清晰。
- 空列表、长文件名、多结果、失败与成功混合时，状态和操作是否容易辨识。
- 下载保留文字按钮且无白底，状态与操作保持垂直居中。
- 桌面双栏、窄屏上下布局；手机操作不拥挤，参数不被裁切。
- 使用均衡/高清/极小预设以及不同格式，处理、重试和下载行为保持现状。

截图、真实压缩业务操作、375px实屏/横屏、文字缩放与macOS/桌面安装包均由用户验收。
完成静态/定向检查不表示上述项目已验收。试点验收前不继续推广。

再次检索并核对：

- `dragging movements --domain ux -n 2`：命中拖动操作需替代入口，采纳质量数值输入和保留键盘操作。
- `safe area fixed actions --domain ux -n 3`：命中固定区、安全区和焦点可见性，采用底部安全区留白和自然滚动，避免叠加固定工具栏。
- `forms --stack vue -n 2`：仍命中校验库和v-model建议。本模块没有复杂表单校验缺口，不引入新库。

再次检索 `touch target compact controls`、`responsive layout tool workspace`、`focus not obscured` 的 UX 结果：采用较大触控目标、避免页面横向溢出、焦点不被布局裁切；不混用原生平台单位，不将一般建议宣称为完整合规证明。
