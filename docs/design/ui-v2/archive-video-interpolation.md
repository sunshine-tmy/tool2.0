# 归档视频智能补帧

2026-11-22 按新的保存流程调整为成片级补帧。复用已发布的 RIFE 能力包及兼容引擎。

## 交互

- 片段“变速”不再提供补帧控件。编辑过程中调整速度或选择片段不会启动补帧推理。
- 视频点击“保存为最新版本”或“导出视频”先打开独立设置弹窗；粗剪、配乐、水印共用此入口。切换功能时的“保存并切换”也先确认输出设置，取消则保留当前编辑页面。
- 输出帧率与补帧开关常显；打开开关后才展开处理方式、质量、切镜保护、兼容回退与能力状态，并触发能力检测。修改选项不创建处理任务；点击“开始处理并保存/导出”才执行。
- 每次打开保存或导出弹窗都默认关闭补帧，不自动沿用上次的开启状态；关闭时提交数据不含补帧参数，后端走普通保存路径。开启时必须明确选择目标帧率。输出帧率仍可独立调整，关闭补帧时只做普通帧率转换。选项保存为 `audioEdit.outputSettings`，与剪辑的画幅、速度、音量设置分开。
- 粗剪、变速、空间变换、字幕、配乐、水印先合成为含完整混音的无损中间文件，再对整个成片统一补帧，最后编码为 MP4。视频保持时长及音画同步。
- 进度弹窗显示合成、补帧、编码、提交阶段，可停止任务；成功前不替换已保存成品。允许兼容回退时，实际使用兼容引擎的提示保留在任务和页面中。
- 旧工程的片段补帧设置停用并在保存弹窗提示确认；历史定格的生成帧取样配方保留，确保取帧结果继续一致。

## 引擎与缓存

兼容引擎使用 FFmpeg `minterpolate` 的运动估计模式，不以复制帧冒充插值。快速、均衡、高质量采用不同的运动搜索参数。切镜开启时先定位镜头时间，再独立处理各镜头，防止切镜提前或出现跨镜头过渡。

AI 引擎使用固定上游 RIFE ncnn Vulkan 20221029 / rife-v4.6。两秒窗口保留前后帧上下文；内部镜头边界不插值。高倍速片段有效帧率已达到目标时直接采样，避免解出不必要的海量图片。GPU 资源错误后使用低占用 CPU 模式重试。只有用户开启“允许兼容回退”，AI 失败才会使用兼容引擎，任务和编辑区会保留回退提示。

每个编辑任务依序处理，取消通过现有子进程生命周期终止 FFmpeg/RIFE；临时目录有空间上限并在结束时回收。切镜保护额外包含剪辑边界和字幕开始、结束时间，避免在字幕切换处跨边界生成重影。

归档暂存目录的 `composition-cache` 缓存完整无损合成及声音，键包含源摘要、剪辑、字幕、声音、水印和画幅配方；补帧引擎、质量和目标帧率不进入该键，重新选择补帧方式时可复用合成结果。总量限制 1 GiB、单项 512 MiB、闲置一小时清理。

`interpolation-cache` 缓存生成的无声画面并使用本次成片音轨，键额外包含补帧参数及模型版本。总量限制 2 GiB、单项 512 MiB、闲置一小时清理。超过单项大小时仍可正常处理，但不长期缓存。

## 能力包与发布边界

桌面端只通过 ComponentManager 的签名清单解析 `video-interpolation`，不读取开发环境 RIFE 地址。未安装时仍可使用兼容补帧。安装后可在编辑器点击“重新检测能力”。能力使用中禁止卸载；安装自检通过受管 FFmpeg 和 CPU 推理实际生成一张中间帧，不需要 Python/CUDA 环境。

候选资产定义：`scripts/component-definitions/video-interpolation.json`。Windows 发行压缩包和必需文件摘要锁定在 `tooling/components/video-interpolation-sources.json`，准备脚本逐文件校验摘要，不下载、不安装、不签名。

```powershell
node scripts/prepare-video-interpolation-component.mjs --source <已解压的固定上游发行目录> --stage <新的暂存目录>
```

2026-11-22 已按现有组件流程生成 Windows x64 正式 Ed25519 签名包、SPDX SBOM 及带 FFmpeg 依赖的完整离线包，并加入源码内置目录。使用现有受信任密钥，既有 12 项能力和信任公钥均保持不变。产物经过生产安装器的离线导入、原生 CPU 中间帧自检以及完整离线包的第二次隔离导入验证。

用户已上传至 `components-v1` Release；2026-11-22 使用生产下载器完整下载归档、SBOM、签名清单，大小及 SHA-256 均与本地签名产物一致。包含新目录和补帧代码的客户端可在线安装。**尚未制作桌面安装器，旧客户端必须更新后才能识别新能力。** 当前可交付材料和校验记录见[补帧能力包交接说明](../../video-interpolation-release-handover.md)。Mac 原生发行锁与硬件验收须在对应平台完成，当前仅制作并验证 Windows x64。

源码调试可显式设置 `TOOLBOX_RIFE_PATH` 和 `TOOLBOX_RIFE_MODEL_DIR`；桌面管理模式忽略这些环境变量。真实引擎测试使用 `TEST_RIFE_PATH` 和 `TEST_RIFE_MODEL_DIR`，不安装到能力目录。

## 验证

- 合成移动图案验证 30/60/120 FPS，以及中间画面位置确实位于原始两帧之间。
- 验证慢放时长、多轨、片尾补齐、音量缓存隔离、切镜、取消清理和原片保留。
- 实际运行上游 RIFE 模型；注入一次设备分配错误后，验证原生 CPU 重试并产生正确中间帧。
- 验证保存和导出先选择参数、取消不创建任务、功能切换取消不跳页、完整字幕成片补帧、合成缓存复用与历史定格恢复。
- 导出检查帧率，视频/音频时长差不得大于目标一帧加 1ms 的容器舍入余量。界面实屏、长时高分辨率与真实 GPU 显存压力测试未作为本次自动验证结果。
