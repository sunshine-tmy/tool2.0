# 公共组件尺寸、状态与响应式规范

版本1.1，2026-11-08。补充根目录 design.md §7、§9；保留现有浅色蓝紫系统。
本文件是实现目标，不表示所有模块已迁移。首个试点为图片压缩，其他模块保持现状直到用户确认。

## 1. 尺寸和基础节奏

| 元素               | 桌面默认                | 紧凑场景       | 手机/粗指针                         |
| ------------------ | ----------------------- | -------------- | ----------------------------------- |
| 普通按钮/输入/下拉 | 高40px                  | 列表按钮32px   | 主操作命中区至少44 CSS px           |
| 上传/提交主按钮    | 高44px                  | 不挤压到图标   | 高44px，窄屏必要时整行              |
| 图标操作           | 图标16–20px，命中区32px | 保留可访问名称 | 命中区44×44 CSS px                  |
| 相邻操作间距       | 8–12px                  | 最少8px        | 最少8px，不用重叠透明区域扩大命中区 |
| 参数字段组间距     | 20px                    | 16px           | 16px                                |
| 字段标签与控件     | 8px                     | 8px            | 8px                                 |
| 面板内边距         | 20–24px                 | 16px           | 16px                                |
| 主要区块间距       | 24px                    | 20px           | 16px                                |
| 上传区             | 高度至少144px           | 不另造极窄版本 | 600px以下至少128px                  |
| 上传与预览/结果    | 16px                    | 16px           | 16px                                |

Web目标以CSS px计；44px是本项目主要触控操作的产品目标，不宣称为所有Web控件的WCAG最低要求。
触控调整同时检查 `pointer: coarse`，不能只按窗口宽度识别设备。
字号沿用14px正文、13px说明、12px辅助；手机可编辑文字优先16px防止系统输入放大，不全局放大所有文本。

圆角：控件8px，上传12px，面板14px，弹窗16px。优先复用变量，不在每个模块维护色板。
模块标题26px/36px、图标64px；窄屏标题24px/32px、图标56px；首页图标48px。

## 2. 按钮与状态

| 状态 | 呈现                                     | 交互与语义                                                          |
| ---- | ---------------------------------------- | ------------------------------------------------------------------- |
| 默认 | 主操作主色实底；次操作描边；行内操作文字 | 高频操作保留文字，图标装饰 aria-hidden                              |
| 悬停 | 主色加深或浅主色背景                     | 不改变尺寸、边框厚度或文字位置；disabled不响应                      |
| 按下 | 颜色反馈，不位移                         | 不靠缩放影响相邻点击目标                                            |
| 聚焦 | 2px主色轮廓、3px偏移                     | 保留键盘焦点，不被overflow或固定栏裁切                              |
| 选中 | 浅主色、主色边界、字重600–700            | 分段按钮用aria-pressed；真正Tab交给组件库管理                       |
| 加载 | 原按钮loading和明确动词                  | 不重复提交，不改变任务取消范围                                      |
| 禁用 | 降低强调，仍可读                         | 使用真实disabled；在邻近区域说明前置条件，不只依赖不可聚焦的tooltip |
| 危险 | 危险色文字/弱底色                        | 确认规则按既有业务，不新增或省略确认                                |

成功/失败不只靠颜色。成功小字使用足够深的绿色；现有 #16A34A 主要用于图形。
青蓝为装饰，不用于白底关键数据。试点可用语义变量与 `color-mix` 生成深色文字，不新增独立色板。
每个任务区一个主动作；下载、清空等结果操作不与“开始处理”争夺主层级。

## 3. 上传、表单与选择器

- 复用 `.file-upload-area[data-upload-area]`。图标28–32px，主文案16px/600，说明13–14px。
- 默认、hover/dragover、focus、不可用、错误、已选分别表达；错误靠近文件或字段，提示不会撑成主列。
- 真实input与既有处理器仍归feature所有；统一外观不建立万能上传器，不改变接受类型/数量。
- 标签关联到真实控件，单位和可选属性写清楚。滑块应命名实际获得焦点的手柄，不能只给外层div命名。
- 下拉选择显示名称，内部值保留原ID；选中项失效按已有规则清理，不显示裸ID。
- 表单值不因视觉调整trim、四舍五入或重置；专用输入的解析由业务实现决定。

## 4. 筛选、批量操作和结果记录

筛选与批量操作分层：搜索/类型/平台/排序一组；选择数量/移动/下载/删除另一组。
宽屏搜索可弹性伸展；下拉需保留可读宽度。窄屏按原顺序换行，不压到几十像素。
刷新置于列表操作区；不新增和删除搜索按钮，按模块已确认方式保留。

记录采用三部分：缩略图与文件信息、状态、操作。文件区 `min-width:0`，名称长时省略或换行且完整名称可访问。
正文靠左；状态与操作垂直居中；操作间距8–12px，不逐行增加阴影。
图片缩略图桌面72px、窄屏56px，固定比例并使用contain/cover表达对应预览职责。
可用宽度不足时操作移到文件信息下方；极窄屏占整行，不因列宽压碎按钮。
保留配音批次“操作始终在下方”的特例。

分页有独立上间距16–20px，总数靠左、页码靠右；窄屏换行，不能与最后一条记录粘连。
仍使用原组件及选择范围，归档分页保留50/100/200/500，不给其他模块擅自增加页容量。

## 5. 弹窗、提示和空状态

- 确认420–480px、普通表单560–720px、媒体详情960–1120px；受真实视口和头部边界约束。
- 头部标题/关闭与内容间距16–20px；内容到页脚20–24px；说明到上传16px。
- 复用组件库focus trap/ESC/返回焦点；遮罩继续避让完整头部，不写死顶部偏移。
- 长内容只在明确区域滚动；桌面标题区、应用顶栏、底部播放器及安全区不能覆盖主操作。
- 普通说明不默认使用整块警告。真正错误保留；能力缺失不能仅通过隐藏提示伪装可用。
- 空状态分别说明“尚未添加”“无记录”“无匹配”“加载失败”，提供当前可用的下一步。

## 6. 工作区与响应式

| 可用场景                    | 排列                                                                       |
| --------------------------- | -------------------------------------------------------------------------- |
| 桌面内容足够                | 主区弹性，参数区约300–340px，间距20px                                      |
| 901–1180px视口              | 保持可读，结果操作可先换到下一行；不得仅因视口宽就假定侧栏之外仍有双栏空间 |
| 900px以下视口或模块容器不足 | 参数区在主区下方；表单与列表按内容换行                                     |
| 560px以下                   | 内边距16px，操作区必要时整行，避免强制最小面板高度制造空白                 |

桌面进入工具时保留模块侧栏和折叠功能，手机改抽屉工具菜单；首页仍集中显示全部分类。
窄容器可用container query补充viewport断点，不以隐藏溢出来掩盖控件被裁切。
表格、时间线、波形允许职责明确的内部滚动；页面本身不因固定列宽横向溢出。
固定播放器需预留底部空间并考虑 `env(safe-area-inset-bottom)`。

## 7. 实施与验收

图片压缩先完成局部试点；用户现已授权全局推广，公共交互规则集中维护，专属工作区布局仍由模块拥有。
每次推广先检查组件现有职责与用户决定；相同外观优先复用，状态机不合并。
交付写清静态检查、实际交互及用户实屏验收的区别。当前不截图、不自动构建、不做全量测试。
按上传区、结果记录、表单/弹窗的职责逐组推广，不重新替换配色或业务组件。

## 8. 移动端试点补充

2026-11-08：用户允许为移动端优化增加必要依赖。优先使用现有 Vue、Naive UI 和浏览器能力；
新增前说明缺口、收益、包体积和许可证影响，不把“允许增加”视为必须引入。
图片压缩试点与后续全局推广均复用现有依赖。

- 图片压缩保持自然滚动；按用户最新决定，不添加“压缩设置”“返回图片”等快捷定位入口。
- 质量滑块保留现有范围和键盘操作，同时提供整数输入；提交采用同一质量状态，不能让空输入向后台提交null。
- 滑块名称需设置在真实获得焦点的手柄上。复用shared/ui/slider-label.ts，旧音频库导出保留兼容。
- 窄屏文件名允许换行，逐条操作附带文件名的可访问名称；下载与删除仍保留可见文字。
- 底部下载和清空可用两列等宽按钮，清除桌面min-width造成的溢出，并给安全区留白。
- 不为突出操作叠加多个固定栏，页面缩放和滚动手势保留浏览器默认能力。

## 9. 全局推广后的代码归属

- `styles/adaptive.css`：移动端按钮至少44×44 CSS px、表单可编辑文字16px、手柄透明命中范围、焦点、分页换行、模块标题56px图标/24px字号、安全区。桌面保留紧凑密度。
- `styles/upload-area.css`、`styles/records.css`：继续负责上传面和音频记录外观；记录手机操作44px，分页保持总数及原选择范围。
- 各feature：内部grid的断点使用现有具名 `tool-content` 容器。按窗口宽度控制的外壳、手机菜单、弹窗不改用这个容器。
- `shared/ui/tool/DeveloperWorkspace.css`：四个开发工具双栏/单栏的共同规则，依然自动换行文本。
- `shared/ui/audio/inline-preview.css`：音频库、提取及转换共用波形控件；窄内容区分行排列，播放按钮保持居中。
- `shared/ui/slider-label.ts`：真实手柄命名/值播报；旧audio-library入口继续重导出，生产调用不引入跨feature内部依赖。

注意：禁止再次给所有数字输入设置100%宽度挤压左侧标签；需要并排的标签与数值使用有界网格，长说明允许自然换行。
全局规则不覆盖视频画布、字幕框选坐标、波形选段、时间线拖动/缩放、移动端浏览器缩放，也不添加快捷定位。
当前未执行截图、构建或全量测试；375px/横屏/iOS/Android/大字体与读屏仍由实际设备验收，不宣称已经完成无障碍合规认证。

## 10. 模块顶部装饰

13个工具通过 `ToolPageHeader` 统一接入 `ToolPageDecoration.vue`，按既有工具ID选择主题轮廓，不改变目录或路由。
图片使用画框/裁切，归档使用媒体卡片，视频使用胶片/字幕刻度，音频使用声波/唱片/转换弧线，开发工具使用括号/点阵/链接，局域网使用设备/传输线。

- 保留现有标题区高度；装饰绝对定位，不为图案增加大横幅，不覆盖整个长页面。
- 使用现有蓝紫/青蓝语义色、轻量SVG与柔和光晕；不替换已批准的立体模块图标，不增加图片或字体下载。
- 视觉集中在标题右侧空白，图案与光晕一起向四周淡出；工作面板、表单、列表、弹窗及媒体编辑区域不叠加底纹。
- 不对标题容器增加隔离混合层，保留已有模块图标白色画布的融合显示。
- 装饰标记 `aria-hidden`，SVG不可聚焦、图层不接收指针；无动画，不改变现有点击、键盘或焦点行为。
- 内容容器600px及以下隐藏SVG，仅保留更淡光晕。系统设置等非工具页面不显示主题图案。
- 仅做必要的组件与静态检查；实屏效果由用户验收，不自动截图、构建或打包。
