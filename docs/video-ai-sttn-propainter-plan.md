## 1. 目标、范围与已确认决策

目标是在现有视频去字幕模块内，接通 STTN 与 ProPainter 的真实本地推理，改善逐帧修复的时间一致性。先完成 STTN，再推进 ProPainter；保留现有 delogo 与 Big-LaMa。

已确认的实施边界：

- 使用预训练权重推理，不训练模型、不下载训练数据集。
- 复用 OCR、手动框选、任务队列、历史记录、容量管理、文件提交和备份恢复机制。
- 继续使用 Python 3.12，不新增第二套 Python 版本。
- 首版以 Windows x64 / NVIDIA CUDA 为目标，STTN、ProPainter 作为可选 GPU 能力；CPU 用户继续使用原有功能。
- 不修改原视频，不改变数据保留、删除、隔离和恢复规则。
- 新能力内容使用新的签名版本，不覆盖或修改旧的已签名归档、版本目录和已安装 generation。
- 后续真正实施前重新核验工作区，保留所有既有未提交和未跟踪内容。
- 桌面安装包由用户自行打包和实装验收；实施者不自动制作安装包、提交、推送或发布。

本方案不表示 8 GB 显卡已经通过 STTN / ProPainter 验收，也不承诺固定处理速度或所有场景下的画质提升。

必备内容：

STTN 权重暂按约 60～100 MB 预留；这是规划预算，最终以选定资产的实际字节数为准。

官方示例包含固定尺寸缩放和固定输出帧率，不直接作为项目的媒体导出命令。解码、时间信息、音轨及最终封装继续由本项目控制。

- 不恢复 STTN 上游的旧 Python / CUDA 环境，不直接复制 Conda 环境或整个上游 requirements。

## 6. 时序推理与媒体处理设计

处理链路：读取视频信息 → 复用 OCR / 手动区域 → 生成逐帧掩膜 → 按镜头组织重叠时间窗口 → 引擎推理 → 提交有效中心帧 → 合成音轨 → 校验并原子保存结果。

### 6.1 重叠窗口与有界内存

一个窗口包含前置上下文、实际输出的中心帧、后置上下文和数量受限的参考帧。只提交中心帧，每个全局帧号恰好输出一次。

- STTN 可从中心 8 帧、前后各 4 帧、最多 4 个参考帧等小配置开始实验；这是待测候选，不作为正式默认值。
- ProPainter 从小子片段、少量邻帧与参考帧开始验证，再固定低显存配置。
- 参考帧限定在同镜头和有界时间范围内，不随视频长度无限累积。
- 明显镜头切换处重建参考关系，避免跨镜头传播背景。
- 明确首尾补边、单帧、尾块不足、字幕出现 / 消失、多个掩膜及不同时间范围的处理。
- 只保存有限的解码帧、参考帧和光流缓存，不将整条视频一次性载入 CPU / GPU。
- 现有 `max_load_num`、`neighbor_length`、`subvideo_length` 等参数的含义需在适配器中明确映射，不能仅修改数值就认定实现了时间重叠。

### 6.2 STTN 区域与尺寸适配

优先验证字幕区域裁剪、模型匹配尺寸的补边或重叠切块，按原坐标回贴。大范围字幕需要验证空间块之间的重叠融合和时间一致性。

不静默将整幅高清视频缩小后再放大冒充原分辨率修复。若某个配置确实采用缩放，必须明确说明并单独验收。网络结构的 patch / 特征尺寸要求按固定上游实现验证。

### 6.3 ProPainter 光流链路

执行光流估计、光流补全、图像传播和修复网络，保留正确的数据关系：

- 连续帧用于相邻光流计算；稀疏参考帧不能当作连续帧计算光流。
- 保留上游要求的 FP32 阶段，例如 RAFT；对适合的网络验证 FP16，不能将全部模块无差别半精度化。
- 尺寸约束优先采用可逆补边和回裁，不静默改变最终几何尺寸。
- 对张量生命周期与缓存峰值单独测试，不能只看到上游有 subvideo 参数就假定内存已经有界。

### 6.4 帧、音轨与提交

- 校验模型输出的帧数、尺寸、通道、类型和有限数值。
- 掩膜外画面在编码前保持原始像素；掩膜羽化 / 膨胀区域需明确，不把有损编码后的字节或像素相等作为断言。
- 复用既有音轨和封装策略，核对帧数、尺寸、总时长和音画同步。
- 核对源帧率和时间戳；变帧率能力按现有链路与真实样本明确支持范围，不用固定帧率示例覆盖原时间信息。
- 在临时位置生成完整结果；文件验证和最终数据库记录均成功后，才发布成功终态。

### 6.5 取消、错误与资源释放

- 在时间窗口和模型阶段之间检查取消，不仅在解码时检查。
- CUDA 单次算子不能任意中断；通过有界工作单元控制等待，并实测取消延迟。
- 成功、失败、取消和准备阶段失败均释放模型、GPU 张量、帧 / 光流缓存、读写句柄、临时文件及容量预留。
- 继续使用现有视频串行队列，不引入跨全项目的 GPU 调度框架，不强制卸载其他业务或其他程序的模型。
- OOM 后可使用同一引擎的已验证低显存配置有界重试；清理本次临时产物并保证整段配置一致。仍失败则如实报告，不静默切换 LaMa、CPU 或分辨率。
- 保留现有错误码；新增必要错误信息要明确映射并补充兼容测试。

### 6.6 进度

按已提交的唯一中心帧统计进度，避免上下文重复计数。显示加载模型、光流估计、修复、合成等真实阶段；最终文件和记录提交前不显示完成。取消后不得继续提交成功。

## 7. 目标硬件、显存与性能门槛

目标参考此前使用的 RTX 3060 Ti 8 GB，实施前重新读取实际显卡、驱动和空闲显存。

ProPainter 官方说明中，1280×720、50 帧、FP16 的示例显存约 19 GB。减小窗口、减少参考帧和区域处理可能降低资源需求，但不能由此直接承诺 8 GB 稳定运行 720p。

| 引擎       | 首轮验证目标                        | 扩展条件                                         |
| ---------- | ----------------------------------- | ------------------------------------------------ |
| STTN       | 720p 常见字幕区域，先以稳定精度验证 | 时间一致性和显存通过后再扩展 1080p               |
| ProPainter | 480p 级处理配置、小时间窗口         | 先通过较低分辨率，再依据实测决定 720p 或区域配置 |
| 两者       | 横屏、竖屏分别测量                  | 相同像素数量也不能省略布局测试                   |

## 10. 测试样本、质量与最终验收

### 10.1 必备回归样本

- 更新失败保留旧 generation、离线资源缺失、旧记录和备份恢复兼容。

### 10.2 质量与性能验证

使用可控合成字幕样本和真实视频：前者具有已知的干净背景，后者由人工检查残字、闪烁、人物变形、接缝和音画同步。

视频中被字幕遮住的真实细节未必可恢复，验收不能承诺还原唯一真实背景。任务成功、文件存在和测试数量增加均不足以证明修复质量合格。
