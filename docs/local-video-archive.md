# 本地视频批量归档

在「多媒体内容归档」点击「批量上传视频」，选择多个文件、按需编辑各自标题，再点击「开始批量归档」。每个文件是一条独立归档；默认标题为文件名，不伪造作者、发布时间或线上作品地址。成功结果使用「本地上传」来源，可在来源筛选中查找，并用已有列表操作批量移动到自定义分组。

上传前可在窗口中选择「归档分组」，本轮新视频自动加入该组；不选择则保存为未分组。分组在本轮执行期间固定，停止或结束后可重选，再重试失败项。若尚无目标分组，可先在主页面新建或刷新分组，再回到上传窗口，已选择的文件仍保留。重复文件保留已有归档的原分组，不因本次选择而移动；已成功的视频如需改组，可使用归档列表的「移动所选」。

支持 MP4、MOV、WebM，每批最多 1000 个文件（含累计追加选择），可一次选择 700 个视频后点击一次「开始批量归档」，自动按顺序处理。单文件最大 500 MiB、最长 2 小时；主机的 `REMOTE_MEDIA_MAX_BYTES`、归档总容量和磁盘剩余空间可能使实际可上传大小更小。需要已安装且可用的 FFmpeg/FFprobe 共享媒体运行时，不需要 Python、模型或平台登录。上传视频原样保存，不重新编码；另生成 JPEG 封面。容器有效且有视频流才会接受，浏览器能否直接播放仍取决于视频编码和设备。

## 进度、重试与停止

- 浏览器按顺序逐个发送文件，服务端流式写入，不把整批或整个大文件读入内存。每项显示上传进度和校验/封面生成状态；文件传输完成不等于归档成功。
- 队列每页显示 20 条，显示总体处理进度、成功/失败/停止数量、所选文件总大小和当前处理的视频；翻页不影响后台顺序。整轮结束或停止后刷新主归档列表，避免每完成一个文件就重新加载列表和视频预览。
- 本地视频归档使用独立的每分钟 1200 次上传额度，覆盖一批 1000 条并留出重试余量；服务端仍逐个处理文件。其他上传、登录和平台获取操作沿用原有额度。遇到限流或并发繁忙（HTTP 429）时显示倒计时，等待 60 秒后自动重试同一文件，每项最多自动重试 5 次；等待时也可立即停止。整体耗时取决于磁盘、网络和封面处理速度。
- 成功后显示「查看归档」。可继续预览、截帧、下载、ZIP 导出、翻译标题、配乐、水印编辑及标记已在其他平台发布，数据沿用现有长期留档、手动删除规则。
- 单项失败不影响其他文件；支持「重试此项」或「重试失败/已停止项」，不会重传已经成功的项。非法格式、空文件或超限文件需要移除并重新选择，不能靠重试绕过限制。
- 以原始文件内容的 SHA-256 去重。相同内容再次上传或网络断开后重试会复用已有本地归档，包括其最新配乐/水印版本，不覆盖已有标题、译文或分组。仅文件名不同不新增副本；重新编码后的不同字节内容视为另一份素材。
- 点击「停止剩余上传」会中止当前传输并停止队列。提交阶段可能已经成功，此时不回滚或删除已完成归档，重试通过内容去重确认结果。
- 上传队列中的浏览器文件选择不会跨刷新或浏览器重启保存。上传期间请保持页面打开；关闭上传窗口或切页时会确认是否停止，刷新/关闭浏览器也会提示。已成功归档的结果始终保留。
- 主机重启后，中断的上传任务标记为失败，不自动重传或重新生成；重新选择文件可通过内容去重确认是否已经提交。

## 数据与兼容

详情中可选择已保存的截帧缩略图，再点击「删除截帧」确认删除。仅移除该截帧，原视频、封面及其他截帧保留；媒体数量、占用空间和 ZIP 内容同步更新。具体规则见[视频截帧管理](./tiktok-archive.md#视频截帧管理)。

本地视频和封面通过现有归档 staging、文件摘要校验、原子目录提交、数据库和文件索引保存到归档 `items/` 目录。上传中断、校验失败、容量不足或提交失败清理本次临时目录；不修改电脑中原文件，也不清理其他归档。正常请求受现有身份认证、Origin/CSRF、速率及并发限制保护；任务运行时阻止卸载所用的 FFmpeg。

新归档与分组成员在同一数据库事务中提交，分组仍由既有成员记录管理，不写入媒体清单。目标分组不存在、处理中被删除或分组写入失败时，本文件归档失败并清理临时文件；不重新创建被删除的分组，也不把未分组的半成品报告为成功。

远程链接获取和 Excel 导入仍只接受原有三个平台。本地上传没有可重新获取的线上来源，因此不显示「原链接」「重新获取」，其刷新 API 返回 `ARCHIVE_LOCAL_REFRESH_UNAVAILABLE`，视频编辑与保存功能不受影响。

元数据数据库升级到 Schema v8，扩展平台约束以接受 `local`。沿用升级前的完整 SQLite 快照与事务迁移，保留旧载荷、子表、唯一索引、外键及历史 v6/v7 回滚备份；不重写历史媒体、译文、时间或文件路径。自动化迁移测试仅在临时数据库中执行。备份时仍须同时保存应用数据库和整个归档数据目录。

接口：`POST /api/v1/tools/media-archive/local-videos`，multipart 字段 `file`、可选 `title` 和可选 `groupId`（已有归档分组的 ID；未分组时省略）；每个 HTTP 请求只提交一个文件，响应包含 `item` 与 `duplicate`。不接受客户端文件系统路径或来源平台字段。浏览器批量队列复用该接口，仅 HTTP 429 自动等待重试；网络断开、校验失败、磁盘或配额不足等其他失败保留明确的手动重试方式。
