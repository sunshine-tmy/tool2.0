# 电商工具箱 UI / UX 全局升级规划

> 规划日期：2026-09-07  
> 适用范围：主项目 `frontend`，不包含 `lan-file-transfer-standalone`。  
> 定位：免登录、本地优先、面向电商素材处理的桌面级工具工作台。

## 1. 设计结论

推荐采用「清爽专业工具台」方向：保留现有蓝色作为主操作色，以青绿色表达本地、安全、可用状态；减少装饰性渐变和无意义色块，通过更稳定的页面骨架、明确的操作层级和一致的反馈，让用户能更快完成任务。

核心体验目标：

- 打开页面后 3 秒内看懂当前模块能做什么、第一步该做什么。
- 每个模块统一为“输入 / 配置 / 执行 / 结果”四段式流程。
- 复杂任务能看到真实进度、当前阶段、预计下一步和失败恢复方式。
- 桌面端优先，同时保证 768px 以上宽度可用；窄屏不出现控件重叠和横向溢出。
- 不改变现有功能、接口和数据逻辑，先完成视觉系统与公共组件，再逐模块迁移。

## 2. 当前体验问题

### 全局层面

- 页面框架已经清楚，但标题、说明、工具栏、内容卡片之间的层级偏平，主操作不够聚焦。
- 多种蓝、绿、橙和灰色直接散落在样式中，状态色、品牌色和模块装饰色的职责不够明确。
- 卡片、输入框、按钮、标签的圆角、边框和阴影强度不完全一致，视觉上略显拼装。
- 页面密度不统一：首页偏松，文件列表与筛选区偏挤，复杂模块容易产生较长的纵向滚动。
- 空状态、处理中、成功、失败和服务不可用的反馈样式缺少统一规范。
- 顶部搜索目前视觉占比高，但工具只有 6 个，实际导航价值有限。

### 已检查页面

- 首页：首屏信息重复，“可用工具 6 / 无需登录 100% / 本地服务 3100”对完成任务帮助有限；工具卡片的入口文字弱于卡片内容。
- 图片压缩：上传区、统计区、结果区、参数区同时展示，初始空状态下视觉重心分散；执行按钮离输入区域较远。
- 局域网文件传输：访问地址卡、Tab、上传区、筛选区连续堆叠，首屏信息密度较高；批量操作和筛选的主次不够清晰。
- 多国语言配音：模块复杂度最高，需要重点处理加载兜底、步骤导航、分段编辑、音色配置和结果下载之间的关系；本次检查时该路由出现空白视图风险，应在视觉改造前先补齐加载与异常边界。

## 3. 视觉方向

### 3.1 色彩

| 角色       | 建议值    | 用途                           |
| ---------- | --------- | ------------------------------ |
| 主色       | `#2563EB` | 主按钮、选中态、链接、焦点环   |
| 主色悬停   | `#1D4ED8` | 主按钮悬停                     |
| 本地安全色 | `#0F766E` | 本地处理、局域网、成功辅助信息 |
| 成功       | `#16A34A` | 完成、服务可用                 |
| 警告       | `#D97706` | 待安装、需注意、即将过期       |
| 错误       | `#DC2626` | 失败、危险操作                 |
| 页面背景   | `#F6F8FC` | 全局底色                       |
| 卡片背景   | `#FFFFFF` | 工作面板与弹窗                 |
| 主文字     | `#172033` | 标题、关键数据                 |
| 次文字     | `#64748B` | 描述、辅助信息                 |
| 边框       | `#E2E8F0` | 卡片、输入框、分隔线           |

规则：模块图标可以使用低饱和辅助色，但交互控件只使用统一主色；绿色不再同时承担“品牌强调”和“成功状态”。

### 3.2 字体与间距

- 字体栈：`Inter, PingFang SC, Microsoft YaHei, system-ui, sans-serif`。
- 页面标题 26/34、模块标题 20/28、区块标题 16/24、正文 14/22、辅助文字 12/18。
- 使用 4px 基础间距：4、8、12、16、24、32、40、48。
- 页面最大内容宽度 1440px；常规工作区内边距 24px，宽屏 32px，窄屏 16px。
- 控件默认高度 40px，紧凑控件 32px，主要按钮最小宽度 112px。

### 3.3 形状、阴影与动效

- 输入框和按钮圆角 8px，普通卡片 12px，重点工作面板 16px。
- 普通卡片只保留 1px 边框；仅浮层、拖拽中元素和重点面板使用阴影。
- 动效时长 160–220ms，只用于悬停、Tab 切换、折叠和结果出现。
- 尊重 `prefers-reduced-motion`，禁用非必要过渡。

## 4. 全局信息架构

### 顶部栏

- 左侧保留产品标识和侧栏折叠按钮。
- 中间搜索改为“快捷跳转”，支持模块名、能力关键词和快捷键 `/` 聚焦；桌面宽度不足时缩为图标按钮。
- 右侧统一为服务状态入口，点击后使用抽屉展示前端、API、Python/模型服务状态，不在顶栏堆叠技术端口。

### 左侧导航

- 固定 224px，折叠态 64px；文字超出使用省略号和 Tooltip，不再撑宽侧栏。
- 模块按任务分组：图片、视频与文案、文件协作。
- 每项只显示图标、短名称和必要状态；“可用”不需要逐项常驻，只有异常、安装中或未安装时展示状态标记。
- 当前模块使用浅蓝底、左侧 3px 指示条和主色图标，避免同时叠加过多强调样式。

### 页面骨架

每个工具页统一为：

1. 页面标题区：标题、单行说明、必要的全局操作。
2. 步骤或模式区：仅复杂模块使用步骤条或 Tab。
3. 主工作区：左侧输入与结果，右侧参数；简单模块使用单列。
4. 底部任务区：历史记录、下载记录和失败重试。

顶部按钮不超过 2 个；危险操作进入更多菜单或结果区批量工具栏。

## 5. 公共组件规划

优先建设以下组件，避免各模块继续复制样式和交互：

| 组件                  | 责任                                   |
| --------------------- | -------------------------------------- |
| `ToolPageHeader`      | 标题、描述、状态、页面级操作           |
| `ToolWorkspaceCard`   | 工具主面板统一边框、间距和标题         |
| `UploadDropzone`      | 点击、拖拽、粘贴上传及限制说明         |
| `TaskProgress`        | 阶段、百分比、当前动作、耗时和取消     |
| `ResultToolbar`       | 选择、批量下载、删除、格式筛选         |
| `EmptyState`          | 空数据、未搜索到、等待上传三类状态     |
| `StatusBadge`         | 可用、处理中、成功、警告、失败、未安装 |
| `ServiceStatusDrawer` | 本地服务、依赖、模型和修复入口         |
| `ConfirmDialog`       | 统一危险操作二次确认，禁止原生弹窗     |
| `ErrorBoundary`       | 页面加载失败、模块异常和重试入口       |
| `MobileActionBar`     | 窄屏固定主操作，避免按钮滚出视口       |

组件必须覆盖默认、悬停、聚焦、禁用、加载、成功和错误状态。

## 6. 各页面改造方案

### 首页

- 移除偏营销式的大面积 Hero，改为紧凑欢迎区：“今天要处理什么？” + 搜索/快捷入口。
- 将 3 个无效指标替换为“最近使用”“进行中的任务”“服务异常”，无数据时不显示。
- 工具卡片整卡可点击，展示最近一次使用时间和一项最关键能力；卡片入口统一为箭头，不重复“打开工具”。
- 增加最近任务区，可直接继续未完成任务或打开结果目录。

### 图片压缩

- 空状态下突出上传区，参数区保留简洁预设；上传后再展开高级参数和结果表格。
- 将“均衡 / 高清 / 极小”明确为预设，并实时显示预计格式、质量和宽度策略。
- 结果列表增加原始/输出格式、压缩比例、尺寸和单项下载；批量下载保持单一主按钮。
- 输出格式变化后在执行按钮附近显示清晰摘要，避免用户不确定设置是否生效。

### AI 图片处理

- “去水印 / 变清晰 / 抠图”继续使用 Tab，但每个 Tab 保留一致的左右结构。
- 未安装环境时展示独立安装卡；安装过程显示真实步骤、日志摘要和可恢复错误，不使用模拟进度。
- 对前后对比类结果提供滑块对比；抠图结果提供浅/深/透明棋盘三种背景预览。
- 将版权提醒保留为轻量提示，避免抢占主操作视觉层级。

### 局域网文件传输

- 局域网地址收纳为可折叠共享条，默认只显示地址、复制和二维码按钮。
- 保留“文件传输 / 图文快传”Tab，Tab 内容完全隔离状态，切换不造成布局跳动。
- 上传区统一支持选择、拖拽和粘贴；粘贴成功后明确提示来源类型和文件名。
- 筛选项超过 3 个时收进筛选弹层；列表上方只保留搜索、排序和批量操作。
- 批量删除使用组件确认弹窗，明确文件数量和不可恢复；移动端批量操作使用底部操作条。

### 视频文本解析

- 使用“上传视频 → 解析中 → 校对文本 → 导出”四步流程。
- 解析中展示上传、提取音轨、识别、整理四个真实阶段；允许离开页面后从任务中心返回。
- 文本结果使用可编辑段落或时间轴视图，不在同一屏同时展示所有辅助信息。
- 导出入口集中管理 TXT、SRT 等格式，并在下载前展示语言与段落数摘要。

### 多国语言配音

- 页面分为“在线配音”和“参考音色克隆”两个一级 Tab，内部再按文案、音色、生成、结果组织步骤。
- 分段编辑采用编号卡片；只有拖拽手柄可排序，输入框区域保持文本选择和编辑能力。
- 智能识别分段使用完整预览，明确展示原文和中文翻译，并允许合并、拆分、重新编号。
- 结果区统一提供分段音频、总音频、单语字幕、中文字幕和双语字幕，并显示语言与随机哈希命名预览。
- 首次进入先渲染骨架屏；模块加载失败时展示错误卡和重试按钮，禁止整页空白。

### 短视频解析

- 输入区只保留分享链接和解析主按钮，并提供支持平台示例。
- 解析完成后将封面、作者和文本作为摘要，视频/图集作为主要结果。
- 多媒体结果统一使用选择模式和批量下载；失败时区分链接无效、平台限制和网络异常。

## 7. 响应式与无障碍

- `>= 1280px`：固定侧栏，双栏工作区。
- `960–1279px`：可折叠侧栏，参数栏宽度 300px。
- `768–959px`：参数区改为抽屉或折叠面板，列表工具栏自动换行。
- `< 768px`：侧栏变抽屉、页面单列、主按钮使用底部操作条；二维码和地址卡不横向溢出。
- 所有输入有可见标签；仅图标按钮必须提供 Tooltip 和可访问名称。
- 焦点环至少 2px，文本和背景对比度满足 WCAG AA。
- 不只靠颜色传达状态；错误同时提供图标、标题和处理建议。

## 8. 实施顺序

### 第一阶段：基础视觉系统（优先级 P0）

- 建立 CSS 设计令牌，替换散落的颜色、间距、圆角和阴影。
- 完成页面头、工作卡、状态标记、空状态、确认弹窗、错误边界。
- 统一按钮层级、表单校验、Toast 和加载状态。
- 修复多国语言配音路由空白风险，确保异常时可见、可重试。

### 第二阶段：高频模块（P0）

- 图片压缩：渐进式参数、结果表格、格式状态和批量下载体验。
- 局域网文件传输：共享条、上传区、筛选工具栏和批量操作。
- 多国语言配音：步骤化流程、分段编辑、进度和下载结果分组。

### 第三阶段：其余模块（P1）

- AI 图片处理、视频文本解析、短视频解析迁移到统一页面骨架。
- 首页替换为快捷启动、最近任务和异常提醒。

### 第四阶段：响应式与精修（P1）

- 覆盖 1440、1280、1024、768 和 390px 视口。
- 完成键盘操作、焦点顺序、减少动效和对比度检查。
- 统一微动效、骨架屏、空状态文案和错误恢复文案。

## 9. 建议代码落点

- 在 `frontend/src/styles/` 增加 `tokens.css`、`components.css` 和 `utilities.css`，逐步拆分当前体积较大的 `global.css`。
- 在 `frontend/src/components/tool/` 建立公共工具组件，模块只保留业务样式。
- `ToolLayout.vue` 负责导航、顶部栏、服务状态与响应式框架，不承载模块业务逻辑。
- 每迁移一个模块就删除对应旧样式，避免新旧规范长期并存。
- 主项目完成并稳定后，再由用户明确决定是否同步到独立版本；本规划不修改独立版本。

## 10. 验收标准

- 首屏主操作在 1440、1024、768px 下均无需横向滚动即可看见。
- 页面中同一时刻只存在一个视觉主按钮；危险操作不使用主色。
- 上传、处理、成功、失败、无数据、服务不可用均有明确界面状态。
- 所有删除操作使用项目组件确认弹窗，不出现浏览器原生确认框。
- 键盘可完成导航、上传触发、Tab 切换、弹窗关闭和主要表单提交。
- Lighthouse Accessibility 建议分数不低于 90；关键文字对比度满足 WCAG AA。
- 图片压缩、文件传输、配音三个高频流程各完成一次桌面与窄屏端到端测试。
- 构建、类型检查和现有测试全部通过，不改变后端 API 行为。

## 11. 建议的第一批改动

第一批控制在可审查范围内，只做以下内容：

1. 引入设计令牌并统一全局背景、文字、边框、圆角和按钮。
2. 重构 `ToolLayout` 和 `ToolPageHeader`，稳定顶部栏、侧栏与内容宽度。
3. 建立 `UploadDropzone`、`TaskProgress`、`EmptyState`、`ConfirmDialog`、`ErrorBoundary`。
4. 先迁移图片压缩作为样板页，验证视觉规范和交互约束。
5. 样板页确认后，再迁移局域网文件传输和多国语言配音。

这样可以避免一次性重写全部页面，同时让后续模块复用已经验证过的模式。
