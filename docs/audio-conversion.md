# 音频格式转换

入口：侧栏「音频格式转换」，或音频素材库、归档视频配乐编辑中的「音频转 MP3」。

- 一次最多选择 1000 个 OGG、FLAC、MGG、MFLAC 文件，每个最大 100 MiB、最长 2 小时。
- 浏览器依次上传并等待转换完成，服务端按单任务队列处理。已接收任务关闭页面后仍继续；未上传文件离开后需重新选择。停止后续上传不会取消已经提交的任务，可在记录中单独取消。
- 默认 MP3 192 kbps，可选 128、256、320 kbps。保留单/双声道，多声道转双声道；不兼容的采样率转 44.1 kHz，保留基本文字标签，不复制封面。
- 原文件不修改。输入临时副本、解码中间文件及密钥在任务结束后清理，转换记录与成功 MP3 长期保存，手动删除。重启不自动重跑中断任务，失败需重新上传。
- 转换模块空间上限 10 GiB，队列按输入和输出预留容量；磁盘不足时拒绝新上传，不删除旧结果。
- 记录支持单条下载、选择后 ZIP 流式下载、取消与删除。加入音频素材库可指定用途与分组，素材库独立保存副本。由归档配乐进入时，加入后返回原视频并选中音乐，仍需手动保存视频编辑。
- 支持全选本页成功结果和逐条勾选，翻页后保留已选内容（每次最多 1000 条），统一选择分组和用途后逐条加入素材库，显示进度及新增/已存在/失败数量。失败项保留选择，可只重试未加入项；已有音频按素材库原有内容去重规则复用，回收站项目需先恢复。批量加入不会自动替视频挑选某一首音乐。
- 新提交的文件按「原文件内容 SHA-256＋MP3 码率」去重，复用进行中的任务或校验有效的成功结果；名称不同不影响判断，失败、取消、结果缺失或损坏的记录不阻止重新转换。更换码率会生成独立结果。旧版记录没有保存输入摘要，因此首次重新提交旧文件时可能仍需转换；不修改旧记录或恢复已清理的原文件。
- kbps 是码率，即每秒音频数据的千比特数。同一音频码率越高，文件通常越大；提高码率不能恢复已丢失的音质。192 kbps 为默认均衡选项。
- 桌面「数据备份与恢复」可单独导出/合并/替换恢复转换记录和结果，不包含临时输入或密钥。旧客户端不认识这个模块，导入请使用支持该模块的版本。

## 加密文件兼容范围

不按后缀假定内容可解码。支持真实 OGG（Vorbis、Opus）、FLAC，以及 QMC2 内嵌 EKey、QTag、musicex V1 文件。QMC2 Map 和分段 RC4 算法采用 MIT 授权的 [QM Unlock](https://github.com/mary20050520/qmunlock) 核心算法的 TypeScript 移植；许可保存在 `third-party/qmunlock-LICENSE.txt`，并保留在代码分发声明中。没有引入其账号读取、网络取密钥或 Python 依赖。

musicex V1 通常不内嵌 EKey，需在对应文件行填写已有的该文件 EKey。不同文件使用不同密钥，不会自动读取 QQ 登录信息、进程或账号缓存，也不调用外部解码服务。未提供密钥、版本不支持、密钥不匹配、文件损坏分别给出明确错误，不生成伪成功记录。没有可用密钥的文件需先从合法来源获得普通音频或已有授权的解码材料。

此前提供的 `DJ OKAWARI - Luv Letter_L.mgg` 已识别为 musicex V1；其缺少内嵌密钥，未取得该文件 EKey 前不能宣称已成功转换。

## 开发与验证

复用已安装的 FFmpeg 能力，不重建能力包、不新增模型。加密算法有独立参考向量；媒体测试使用生成的短音频及临时数据库，不把用户音乐放入 Git。
