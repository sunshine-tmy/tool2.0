# Python 运行时统一迁移

## 目标和兼容边界

新的 Windows 能力包统一到固定的 `python-312`（3.12.14-20260901），不再新装第二套 Python 3.11。
`edge-tts`、`image-ai`、`chatterbox`、`chatterbox-cuda` 使用带 `py312` 的新版本号；`xhs-archive` 和 `xhs-translation` 原本已依赖 3.12。
共享的是基础解释器，不是 site-packages：克隆依赖 NumPy 1，而图片处理依赖 NumPy 2，必须继续隔离 venv。

不能修改旧签名清单、将 cp311 wheel 改名为 cp312，也不能提前隐藏或卸载仍被已安装能力依赖的 `python-311`。
旧版运行时识别、自检和签名包兼容逻辑保留。新包准备器强制检查 Python 3.12，并允许合法 stable-ABI wheel、拒绝不兼容的原生 cp311 wheel。

## 源码构建和独立验证

使用新的 `.package/python312-migration/` 目录，避免覆盖现有 stage、模型或开发 venv。
锁定依赖时保留已审核的版本，不顺带升级传递依赖：

```powershell
pnpm lock:python -- -PreserveVersions -Python .package/stage/python-312/python/python.exe
```

可以通过 `-Uv <uv.exe 路径>` 指定构建工具，通过 `-OutputDirectory <新目录>` 先生成待审核锁。日后主动更新依赖版本时，不使用仅供解释器迁移的 `-PreserveVersions`，避免旧约束阻止新版本解析。
能力包准备器默认读取项目内的锁。每个新 wheelhouse 必须用 Python 3.12 创建全新 venv 执行 `pip install --no-index --require-hashes` 和 `pip check`。
克隆源码仍固定官方提交 `65b18437192794391a0308a8f705b1e33e633948`，模型及 CUDA 12.4 版本不因本次迁移变更。
源码环境的安装脚本支持 `-VenvPath`；检测到已有非 3.12 环境会拒绝修改，要求另建目录。
克隆准备器还支持 `--source-vendor <固定提交的 vendor 目录>`，会核验官方提交元数据并拒绝复制原生库；这只复用纯 Python 源码，不复用旧解释器或 cp311 依赖。

验收必须分别覆盖在线配音自检、图片 CPU 依赖导入和模型推理、克隆 CPU 自检和短样例、CUDA 依赖导入和短样例。
仅成功解析依赖或通过静态测试不代表模型推理通过。资源不足时不卸载用户已加载的模型；等待资源可用后再执行实际推理。
Mac 锁生成也统一使用 3.12，但必须在 Apple Silicon 原生构建并验收，不能以 Windows 验证代替。

## 能力包发布门禁

1. 先完成上述离线安装、自检和实际推理。
2. 使用原受信任 Ed25519 私钥为四个新版本生成真实归档、SBOM 和清单；私钥不得进入仓库、stage、报告或 Release。
3. 在新的 feed 目录中放入新包及仍保留的能力。不要将含重复版本或已移除模块的旧 feed 整目录用于组装。
4. 新 feed 只保留一个共享 Python：`python-312`；所有 Python 能力均声明 `expectedPythonVersion=3.12`。删除的是待发布 feed 中的旧条目，不是用户已有安装目录。
5. 经授权发布不可变的 HTTPS 资产并核对远端摘要后，用 `pnpm components:catalog-python312 -- --feed <新 feed 目录>` 生成并审核嵌入目录。此入口在签名/资产校验后额外拒绝混用两套 Python。未发布资产前，不修改 `catalog.generated.ts` 指向不存在的 URL。
6. 桌面安装包由用户另行构建；随后在干净机器完成安装、自检、任务及卸载验收。

本地未配置签名私钥或尚未核验所有新资产时，迁移只处于准备阶段；现有桌面目录仍可能显示两套 Python，不应宣称已完成替换。
存量用户的旧安装会在能力管理中显示“Python 3.11 旧运行时”，只提供确认后的卸载，不提供安装、重装或导入；新用户不显示此项。
卸载前检查各旧能力是否全部更新为受信任的 3.12 清单，损坏或无法识别的旧安装也会阻止卸载。任务、等待队列、安装或音频播放期间拒绝操作，停止回调后再次复核；仅可删除受管根目录下固定的 `python-311`，链接或越界路径拒绝删除。
以上升级流程还须在新桌面安装包上实机验收，不以本地源码单元测试代替安装版验收。
全部能力升级成功且确认没有旧依赖前，不允许卸载 Python 3.11；旧模型、音频、参考音色、归档和数据库始终保留。

## 本次 Windows 版本与升级顺序

2026-10-21 已将下列新版本发布至现有 `components-v1` 组件源，并在远端 SHA-256 与公开下载地址核验通过后更新 Windows 内置目录。旧版本资产不覆盖、不删除；安装版仍需重新构建后使用新目录。

| 能力                   | 新版本               | 共享运行时  |
| ---------------------- | -------------------- | ----------- |
| 在线自然音色           | `7.3.1-py312-1`      | Python 3.12 |
| AI 图片处理            | `1.0.0-py312-cpu1`   | Python 3.12 |
| 参考音色克隆 CPU       | `1.0.0-py312-cpu1`   | Python 3.12 |
| 参考音色克隆 CUDA 扩展 | `1.0.0-py312-cu1241` | Python 3.12 |

新安装只提供 `python-312`（`3.12.14-20260901`）作为 Python 共享运行时；各能力的隔离环境仍然保留，不要求系统预装 Python。

存量安装升级应用后，请在没有任务、安装作业和音频播放时执行：

1. 在能力管理中安装或确认 Python 3.12 共享运行时可用。
2. 对显示“待更新”的已安装能力点击“更新”；先更新 CPU 克隆基础能力，再更新已安装的 CUDA 扩展。没有使用的能力无需新装。
3. 确认所用能力自检及实际任务正常。旧 Python 3.11 条目不再列出被依赖能力后，才可确认卸载旧运行时。

应用不会自动删除旧 Python 或在启动时更新全部能力。新能力下载失败时，不应先卸载旧运行时；重新更新对应能力即可。
历史签名资产保留在原组件发布源，不能用新包覆盖同名旧包。此次迁移不包含桌面安装包构建，也不代表已完成干净机器的安装版验收。
