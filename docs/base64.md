# Base64 编解码

入口：左侧「开发工具 → Base64 编解码」或首页工具卡片；页面为 `/tools/base64`。

## 文本与文件

- 默认「编码 / 文本 / 标准 Base64」。输入 UTF-8 文本，点击「开始编码」。中文、Emoji、空格、换行及 BOM 保留，不执行 `trim` 或 Unicode 归一化。
- 编码文件：点击「导入文件」或拖入一个文件，按原始字节编码。文件只读取到当前页面与 Worker，原文件不会改动。输出下载为 `原文件名.base64.txt`。
- 解码：切换「解码」，输入 Base64 或导入 UTF-8 编码的 Base64 文本文件。输入文件本身的 BOM 视为非 Base64 字符并定位提示，不静默移除。
- 结果为 UTF-8 文本时可复制或下载为 `decoded.txt`；下载使用解码原始字节，保留 BOM 和控制字符。
- 结果不是有效 UTF-8 时显示「二进制结果」，允许下载为 `decoded.bin`，不替换为乱码，不自动执行、渲染或推断文件类型。
- 空文件编码产生有效的空结果；空白页面保持待输入状态。编码的文本空格和换行属于实际输入，不会忽略。

标准 Base64 编码使用 `+`、`/`，保留 `=`；Base64URL 使用 `-`、`_`，输出省略末尾 `=`。解码按所选字母表验证，不允许混用。

解码兼容合法省略的末尾填充：标准 Base64 给出补齐提示，Base64URL 省略填充属于正常情况。错误长度、位置/数量错误的 `=`、非零尾部填充位明确拒绝，不生成伪成功结果。

解码默认勾选「忽略输入中的空格与换行」，只忽略 ASCII 空格、Tab、CR、LF；取消勾选后这些字符也会报错。错误行列和选区始终对应原始输入。Data URL、URL 百分号编码或整段 JWT 不会被自动拆解。

## 交互和保留

- 输入、方向、输入类型、字母表或空白选项改变后，旧结果失效，重新处理前禁止导出。
- 小于等于 200 KiB 的文本默认在输入停止约 300 毫秒后自动处理，可关闭。文件和大文本使用按钮手动处理。
- 可停止当前任务；文件重试会重新读取 `File`，不复用已经转移到 Worker 的失效缓冲区。
- 清空或离开页面终止旧任务，迟到的读取和 Worker 回复不能恢复已清空内容。
- 内容只保存在当前页面内存，不上传、不写入数据库、日志、localStorage 或业务备份。复制、下载由用户主动执行，Base64 本身不提供加密保护。

## 边界与实现

| 项目     | 限制                                            |
| -------- | ----------------------------------------------- |
| 编码输入 | UTF-8 文本或文件最大 5 MiB                      |
| 编码输出 | 标准格式最大 6,990,508 字节，约 6.67 MiB        |
| 解码输入 | 最大 7 MiB，含输入空白                          |
| 解码结果 | 最大 5 MiB，分配缓冲区前检查                    |
| 每次处理 | 最长 5 秒，包含已选编码文件的读取；可停止、重试 |

页面首次加载需要桌面或 Web 服务提供静态资源。加载后编解码在独立浏览器 Worker 进行，无外部网络、模型、Python 或新增运行时依赖。桌面 LAN 网关沿用浏览器工具规则，只增加页面入口，没有 `/api/v1/tools/base64` 内容处理接口。

源码集中在 `apps/web/src/features/base64/`：`processor.ts`、`processor.worker.ts`、`useBase64Codec.ts` 和 `page.vue`。既有 JSON 工具源码与数据保留方式保持不变；工具注册与导航追加 Base64，业务备份仍为原有八项。
