# 数据备份与恢复

桌面设置 →「数据备份与恢复」，地址 `/settings/data-backup`。选择一个、多个或全部模块，导出 ZIP 备份，再在另一台设备的同一入口导入。源码 Web 与 LAN 网页不开放这组系统操作。

## 使用方式

1. 在来源设备结束生成、获取、上传和播放，选择需要备份的模块；可选包含归档展示方式、音频库最近分组和播放队列。
2. 点击「选择位置并导出」。一致快照完成后后台服务恢复，打包从快照继续执行。完成前的 `.partial` 文件不是有效备份。
3. 将最终 ZIP 复制到目标设备。目标设备需使用支持该备份协议的客户端；运行环境和模型继续通过能力管理安装或离线导入。
4. 选择 ZIP、选择包内要恢复的模块，再选择合并或替换并预检。查看现有/备份记录、新增、跳过、冲突、到期记录和额外空间需求。
5. 确认导入。目标设备先保存所选模块的恢复点，完成文件和数据库提交、正常重启后才报告完成。预检后数据变化、文件变化或超过 30 分钟，需要重新预检。

合并默认保留目标已有内容：同一个平台作品按 `platform + contentId` 识别，保留目标整条归档及其编辑、分组和发布标记；普通 ID 冲突重新编号并映射关联。音频库保持原有合并语义，重复备份通过回执和实际记录/文件校验防止重复新增。

替换只作用于所选模块。备份中的空模块会清空该模块现有数据，需要在预检后明确确认；没有选择的模块不参与替换。

## 数据范围

| 模块         | 数据                                                                                                            |
| ------------ | --------------------------------------------------------------------------------------------------------------- |
| 图片压缩     | 现存任务、压缩产物与文件索引，包括仍受索引管理但进度任务已裁剪的产物；应用未保存的原图无法补导出                |
| AI 图片      | 任务、输入、蒙版、结果、商品图配方与独立编辑素材快照；受管绝对路径在目标设备重新定位                            |
| 多国语言配音 | 两种引擎的任务、批次、片段、文案、参数、音频、字幕、永久参考音色和授权记录                                      |
| 音频素材库   | 全部素材、背景音乐、分组、文案、备注、回收站和播放预设；保留独立音频副本与清单恢复机制                          |
| 多媒体归档   | 作品、原文/译文、媒体、封面、截帧、原片、最新成品、配乐/水印快照、分组、发布标记、水印库/轨迹预设与批量归档历史 |
| LAN 文件传输 | 已完成文件、图文便笺及图片、创建/到期时间、下载次数；不包含未完成分片和续传令牌                                 |

不包含模型、能力运行环境、依赖缓存、日志、浏览器登录状态、Cookie、会话令牌、管理员 PIN、`.env` 和签名私钥。未保存的页面草稿不属于持久业务数据。

仅恢复多媒体归档也能保留成品、原片和已保存的配乐/水印，不要求导入音频库。来源关联仅在可靠映射后链接；无法确认的跨设备音乐/配音来源指针不会关联到目标设备同 ID 的无关对象。素材文件、原文和授权信息不因此丢失。

保持各模块原有时间、有效期、永久留档及手动删除规则。已到期记录会在预检提示，正常启动后仍可能按原规则清理；不会延长成永久数据。进行中的任务不能作为可续跑现场导入。

## 恢复点、取消与失败

恢复点保存在桌面数据根目录的 `module-backups/restore-points/`，位于业务 `data` 目录之外，不纳入下一次业务备份。Windows 安装版通常对应 `<安装目录>/data/module-backups/restore-points/`。具体根目录以桌面设置显示为准。

恢复点长期保留，只能显式删除。回滚会替换这些模块在恢复点之后的变化，也会先备份当前状态；其他模块不参与回滚。清单不完整的恢复点保留目录、显示异常，不能当作有效恢复点使用。

复制、扫描、校验与打包可取消；文件/数据库切换阶段必须安全收尾。取消或失败不会把旧版本直接丢掉。若数据库已提交而重启失败，应先查看操作记录和恢复点，不要连续重复覆盖导入。

启动前读取持久恢复日志：未提交的文件切换回滚，已提交的文件核验后完成收尾。核验失败会保留日志和旧副本并阻止业务启动。没有可验证的恢复依据时不会盲目继续。

## 格式及实现边界

- ZIP64，协议标识 `toolbox-module-backup`、协议版本 1；每模块独立版本。
- `manifest.json`、`modules/<id>/records.json`、`modules/<id>/files.json` 和 `objects/<sha256>`；相同内容在包内可去重，恢复后仍按模块独立拥有文件。
- 复用 `archiver`、`yauzl`、SQLite façade、音频库合并器和桌面维护握手；没有新增模型、Python 依赖、HTTP 恢复接口或通用 IPC 执行入口。
- 固定 IPC 方法和短期文件选择令牌；拒绝危险路径、链接、重复条目、损坏摘要、不兼容版本、越过模块归属的文件以及危险媒体链接。
- 后台离线 helper 为 `resources/backend/dist/data-backup-entry.js`，在正常后端编译中生成，资源 staging 必须检查此文件存在。
- 扫描解包、导出快照和预检计划写入备份工具自己的 `work` 目录；成功、取消或失败收尾，以及下一次启动恢复后清理。文件切换暂存位于业务存储根下的 `.module-restore-<操作编号>`，以保证同盘重命名；有日志的切换目录由恢复流程核验后清理。恢复点与日志不按缓存清除；断电前尚未建立日志的孤立暂存目录保留，不盲目删除。

公共任务进度表现有上限为 1000 条，领域任务/永久素材是独立存储。若恢复后启动投影可能超过上限并影响未选模块，预检拒绝操作，提示扩大选择范围或先备份整理历史；不会自动裁掉未选模块的数据。该限制来自当前 `createTaskStore` 和各领域启动投影，不在本功能中改写任务保留策略。

### 2026-10-31 桌面序列化修复

导出及导入预检曾将 Vue 响应式模块数组直接交给桌面桥接，Electron 会报 `An object could not be cloned`。现在两处均发送独立的普通数组快照；不改变备份范围、合并/替换策略或数据保留规则。回归测试通过实际结构化克隆模拟传输，修复前两种操作均复现失败，修复后备份页面 11 项定向测试通过，并验证页面后续改选不会改动已提交参数。此前的普通函数 Mock 未覆盖这一传输约束。
