## 1. 目标与范围

将产品中的“小红书内容归档”升级为“多媒体内容归档”，首期支持小红书与抖音。两个平台共用归档列表、详情、媒体存储、翻译、截帧、下载和管理能力；平台差异集中在链接识别、内容解析、文本规范化、登录与解析运行时。

维持现有主要布局和操作顺序：粘贴分享文案或作品链接 → 获取并存档 → 浏览结果 → 翻译、截帧、下载或管理。

首期处理单条已发布作品的分享链接，包括抖音视频、图集，以及经验证能完整提取的实况/动态图文。保留小红书现有图文、视频和 Live Photo 能力。评论、用户主页批量采集、合集抓取、直播录制、TikTok 和其他平台另行规划。

“功能一致”指可归档作品在本机拥有相同操作能力，不表示两个平台提供完全相同的原始字段，或所有链接在任意登录状态下都能访问。

## 2. 当前实现与需要解除的绑定

以下是 2026-09-30 规划时的源码基线，不代表当前实现；实时状态以第 8、10 节及验收证据为准：

- 共享 DTO 使用 `XhsArchiveItem`、`noteId` 等小红书命名，尚无归档平台字段。
- 获取服务直接调用 XHS Worker 的 `/extract`，链接解析和登录 Cookie 也与小红书绑定。
- 去重依据是 `findByNoteId(noteId)`；多平台必须改用平台与作品 ID 的组合。
- SQLite 归档与媒体领域表为 `xhs_archives`、`xhs_media`；翻译外键关联现有归档表。
- 已存在本地媒体预览、Range 视频播放、详情、搜索分页、单张下载、ZIP、刷新、删除、翻译编辑与批量翻译。
- 已存在暂停保存原分辨率 PNG 截帧、来源时间信息、显眼截帧标识和刷新保留截帧的逻辑。
- 现有短视频模块支持抖音平台识别及第三方 Provider 解析，但结果是短视频解析 DTO，缺少完整归档身份、登录管理和持久化流程，不能直接替代归档服务。
- 桌面版共用前后端源码，解析与翻译依赖通过能力管理安装；同步验收必须检查最终安装包，而不止检查 `.stage`。

重点涉及：`packages/shared/src/xhs-archive.ts`、`backend/src/modules/xhs-archive/`、`frontend/src/modules/xhs-archive/`、工具注册与路由、SQLite Repository、能力管理、清理分类和桌面打包。

## 4. 页面与交互

1. 导航、页面标题、搜索入口、服务状态和能力设置统一显示“多媒体内容归档”。页面副标题明确“小红书、抖音”。
2. 输入区提供“自动识别 / 小红书 / 抖音”，默认自动识别；识别结果在提交前显示。多个链接不静默只取第一条。
3. 获取动作保留“获取并存档”。进入抖音任务时使用抖音环境、登录与错误提示，原有小红书任务表现保持。
4. 任务区显示当前平台和现有步骤进度。需要登录时显示“登录抖音并重试”，失效登录不无限循环重试。
5. 列表增加“全部平台 / 小红书 / 抖音”筛选。平台和内容类型徽标分开放置，不遮挡选择框、封面及截帧标识。
6. 列表筛选或分页变化时明确重置当前页选择；批量删除/翻译仍按显式选择的归档 ID 执行。无选择的“补全未翻译内容”限定当前筛选范围，并显示数量。
7. 详情展示来源平台、作品 ID、原始文案、作者、发布时间和打开原作品入口；共用媒体画廊、翻译编辑与截帧。
8. 运行时状态分平台展示。抖音组件尚未安装时可以继续使用小红书，并可离线查看抖音旧归档。

## 5. 平台适配与抖音解析验证

统一归档服务消费规范化结果；每个平台适配器负责识别作品、准备运行时、解析以及平台文本与登录状态处理。规范化结果至少包含 `platform`、`contentId`、标准作品 URL、原始文本、作者、时间和有序媒体来源。

共用归档服务负责任务队列、远程下载、安全校验、摘要、存储配额、原子提交、刷新与保留用户内容。适配器只返回待保存的数据，不直接写生产数据库或永久媒体目录。

### 5.1 候选解析器与决策门槛

优先验证 DouK-Downloader（仓库历史名称 TikTokDownloader）的本机适配方案。上游列出抖音视频、图集、实况及 Web API；同时明确停止维护加密参数算法，因此目前只作为候选，不能将“已集成依赖”等同于“可稳定解析”。其 `/douyin/detail` API 有作品 ID、Cookie 和原始响应等输入。

候选来源：

- [DouK-Downloader 仓库、能力清单与维护说明](https://github.com/JoeanAmier/TikTokDownloader)
- [上游 Web API 实现](https://github.com/JoeanAmier/TikTokDownloader/blob/master/src/application/main_server.py)

MA01 使用经授权的真实测试作品验证短链、视频、图集、登录和完整媒体下载，再决定具体适配器、固定提交和依赖锁。实况能力单独验证；上游功能声明不足以通过验收。记录真实验证日期、上游提交、平台、运行环境和失败分类，不记录 Cookie 或完整敏感响应。

现有短视频 Provider 可作为显式配置的可选解析来源，但必须满足完整归档契约。不得默认静默切换服务、外发登录 Cookie，或把“只返回预览”作为获取成功。

若候选无法通过基础视频和图集验证，先形成具体失败证据并调整适配方案；不继续安装分发和对外宣称抖音已可用。不得将未经验证的新签名实现混入通用归档重构。

### 5.2 登录、安装与运行边界

- 用户在本机独立抖音浏览器配置中登录；Cookie 和浏览器 Profile 按平台分开保存。
- 登录成功需通过实际解析能力确认，不能只检测到任意 Cookie 就宣布就绪。
- Cookie 仅交给受管本机适配器，Worker 监听回环并验证访问令牌。不同平台凭据不可混用或进入日志/API 响应。
- 复用浏览器发现、受管 Python、生命周期管理和现有代理设置；解析依赖使用独立环境，避免污染 XHS 环境。
- 桌面设置增加“抖音归档”能力，复用通用“内容翻译”能力；XHS 能力保持可用且不重复下载模型。
- 新能力包采用固定源码提交、依赖哈希、SHA-256、签名、SBOM 和上游许可证说明，失败时可修复或回退。
- 按当前项目支持矩阵验证 Windows x64 和 macOS Apple Silicon；未提供能力包的平台必须明确显示不可用。
- 验证码和访问限制由用户正常完成或稍后重试；本期不增加自动绕过逻辑。

## 6. 统一数据、兼容与文件一致性

### 6.1 归档身份与 Schema

新增平台无关的共享 Schema/类型，建议命名 `ContentArchiveItem`、`ContentArchiveMedia`、`ContentArchiveTask` 和 `ArchivePlatform`。

- `platform` 首期为 `xiaohongshu | douyin`；`contentId` 为平台作品 ID。
- `id` 继续是本地归档 ID，旧记录 ID、媒体 ID、文件名和用户生成截帧保持。
- Repository 查询和 SQLite 唯一约束使用 `(platform, content_id)`，不以 URL、标题或作者作唯一键。
- 无平台字段的旧记录回填 `xiaohongshu`，`contentId` 从旧 `noteId` 获取。迁移前检查重复/异常记录，不自动删除冲突数据。
- 话题、作者、时间和媒体信息允许平台真实缺省；尺寸、时间、字节数按统一单位规范化。
- 原始正文保留；小红书表情和话题处理继续仅在 XHS 适配器执行，抖音文案使用独立规则。
- 实况保存静态图与视频的配对信息。截帧来源继续保存来源媒体 ID/时间，必要时补充来源摘要以说明历史画面。

### 6.2 最小迁移范围

本期保留现有物理媒体目录以及 `xhs_archives`、`xhs_media` 表名，由统一 Repository 隔离这些历史名称。新增平台/作品 ID 真实列及唯一索引，不为命名一致性重写媒体路径或重建翻译外键。

旧记录的媒体路径、清单和 SQLite 数据在迁移后仍能恢复。JSON/manifest 继续只作为迁移输入或恢复清单；SQLite 是元数据事实源。翻译任务和文件索引继续引用稳定本地 ID。

Schema 升级采用当前版本之后的前向迁移，自动备份并提供 dry-run、校验与整库回滚。旧媒体目录不搬迁；物理表/目录中性更名如有需要，另立数据迁移任务。

### 6.3 刷新与用户内容保留

- 获取/刷新先下载到同盘 staging，完成格式、大小、摘要和配额校验后提交。
- 必需媒体任一失败时维持现有“旧归档不被覆盖”行为；新归档不得以空媒体冒充成功。
- 同作品并发获取/刷新通过单作品锁与数据库唯一约束防重；共享配额在最终提交时再次核算。
- 媒体身份优先依据平台来源 ID、媒体类型/序号与摘要稳定映射，不能依赖会过期的 CDN 查询参数。
- 刷新保留截帧及手工编辑译文；源文本变化时标记翻译需要更新，保留用户编辑痕迹。
- 源视频改变时，已截帧仍保留并标明历史来源，不将旧画面强行绑定至新视频。源视频未改变时保持媒体 ID 与截帧关联。
- ZIP 包含平台信息、原始文本、现有译文、元数据和全部媒体；截帧文件仍采用序号/时间区分。
- 一般缓存清理保留永久归档和平台登录态；永久归档删除沿用既有高风险确认策略。更名不能改变实际清理权限或默认选择。

## 7. API、路由与安全

建议新正式入口为 `/tools/media-archive` 与 `/api/v1/tools/media-archive`，新前端全部使用中性共享 Schema。任务事件继续复用 `/api/v1/tasks/:id/events`，不另造平台 SSE 协议。

| 接口                             | 规划行为                                                                |
| -------------------------------- | ----------------------------------------------------------------------- |
| `POST /items`                    | `{ url, platform?: auto/xiaohongshu/douyin }`，返回 HTTP 202 获取任务   |
| `GET /items`                     | 增加 `platform=all/xiaohongshu/douyin`；保留 keyword/type/page/pageSize |
| `GET /items/:id`                 | 返回含平台、作品 ID 的完整统一归档详情                                  |
| `POST /items/:id/refresh`        | 按原归档平台刷新，不能从客户端任意切换平台                              |
| `DELETE /items/:id`              | 保持单条删除和现有批量管理调用行为                                      |
| `GET /items/:id/media/:mediaId`  | 本地预览/下载，视频 Range 契约保持                                      |
| `POST /items/:id/frames`         | 沿用 PNG、来源视频 ID、帧时间及校验规则                                 |
| `GET /items/:id/download.zip`    | 流式导出，包含原媒体和截帧                                              |
| `GET /tasks/:taskId`             | 返回统一平台获取任务                                                    |
| `DELETE /tasks/:taskId`          | 取消排队/读取/下载任务；原子提交期间返回 409，不制造半提交数据          |
| `GET /runtime`                   | 返回分平台解析环境/登录状态与共享翻译状态                               |
| `POST /auth/:platform/start`     | 创建该平台登录会话                                                      |
| `GET /auth/:platform/:sessionId` | 查询平台绑定的登录会话                                                  |
| 翻译相关接口                     | 将现有单条、批次、查询、编辑和重置接口迁入中性命名空间                  |

旧页面路径在过渡版本重定向到新页面。旧 `/api/v1/tools/xhs-archive/*` 通过薄适配层复用同一服务，保持小红书旧 DTO，并只处理小红书记录；旧客户端不得收到不兼容的抖音 DTO。记录兼容范围与移除版本，避免长期保留两套业务实现。仍不恢复历史 `/api` 非版本化路径。

安全要求沿用现有 local/lan 权限、CSRF、限流、队列额度、SSRF、已验证 IP 连接及逐跳重定向检查。新增抖音域名按确切域名/真实子域匹配，不使用任意包含字符串的匹配。媒体地址即使来自解析器也要重新校验；凭据按目标主机精确附带，跨域重定向不得携带平台 Cookie。

错误统一采用归档错误码并带 `platform` 和 `requestId`：链接不符、组件未安装、需要登录、内容不可见、解析失败、限流、媒体失败、配额不足和提交失败分别处理。兼容接口映射旧 XHS 错误码，避免改变当前小红书提示。

## 9. 测试与最终验收

### 9.1 自动化测试

- 共享 Schema：平台枚举、身份、字段缺省、旧 DTO 映射、正文/话题与实况配对。
- 适配器：分享文案、长短链接、多链接、平台不符、重定向、过期会话、错误响应、作品缺失和媒体顺序。
- Repository：相同数字作品 ID 的跨平台记录共存、同平台重复获取、迁移幂等/回滚、外键及文件索引。
- 存储：完整与部分下载失败、并发提交、磁盘不足、配额竞争、提交回滚、重启与媒体摘要。
- 刷新：稳定媒体身份、手工译文保留、stale 标记、截帧保留及视频变化后的历史来源。
- API：成功/错误 Schema、状态码、任务事件、旧小红书兼容接口、Range 和 ZIP。
- 前端：平台识别/筛选、翻译编辑、取消/卸载、SSE 降级、播放器解码门禁、PNG 导出失败与保存成功。
- 安全：域名伪造、私网及重定向、越权删除、CSRF、Cookie 跨域泄漏和敏感日志。

常规 CI 使用固定夹具和 mock，不依赖在线平台可用性；真实链接验证独立记录并在首次接入和发布前执行。

### 9.2 必须完成的实际操作

1. 备份现有小红书归档后升级，验证列表、详情、图片/视频、译文与历史截帧均保持。
2. 小红书与抖音各归档一条视频和一条图集，确认平台、文案、顺序、封面和大小。
3. 验证支持的实况作品，确认图片/视频配对；若不支持则明确提示，不能仅保存封面后宣布成功。
4. 对抖音视频暂停保存 PNG，检查分辨率、时间、截帧图标、单张下载及 ZIP。
5. 翻译、手工编辑、再次翻译、刷新原文，验证一致的编辑与冲突语义。
6. 重启并断开网络，确认已保存内容的浏览、播放、下载正常。
7. 登录失效后重试；模拟解析故障/媒体失败，确认旧存档完整保留。
8. 对实际最终安装包执行同目录覆盖升级，验证数据库、归档、音色、模型、登录状态和其他模块数据保留。

最终通过：`pnpm check`、`git diff --check` 与定向测试通过，既有覆盖率门槛维持；支持平台的构建/能力包/安装验收通过。既有门禁问题必须单独记录，不能以跳过门禁或降低门槛代替验收。
