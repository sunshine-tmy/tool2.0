# TikTok 公开作品归档

视频也支持添加图片水印、设置运动轨迹并保存为最新版本，见[归档视频水印](archive-video-watermark.md)。

更新日期：2026-10-31。此功能在现有多媒体归档领域内扩展，沿用原有任务、SQLite、媒体目录、配额、翻译、截帧、ZIP 和删除流程。

## 使用

1. 重启 API；源码使用原有 `start.bat` / 启动命令。
2. 打开“多媒体内容归档”，粘贴一条 TikTok 视频或图集作品分享链接，来源选择“自动识别”或“TikTok”。
3. 点击“获取并存档”。完成后可按 TikTok 筛选，在详情中预览、下载、翻译、编辑译文、截帧或导出 ZIP。

单条入口支持 `https://www.tiktok.com/@作者/video/作品ID`、`/photo/作品ID`、`https://vt.tiktok.com/短码/`、`https://vm.tiktok.com/短码/` 及 `https://www.tiktok.com/t/短码/`。分享文案中只能包含一条作品链接，主页使用独立的 [TikTok 主页批量归档入口](./tiktok-profile-archive.md)。单条读取仍不支持直播、私密内容、登录或验证码处理；主页列表读取需要现有归档浏览器，必要时由用户正常操作该独立窗口。

无需安装新的模型、Python 依赖或能力包。翻译继续使用现有中译英能力，不代表新增任意语言翻译支持。不会读取浏览器 Cookie 或登录资料，不修改已签名包。

## 视频截帧管理

所有来源（小红书、抖音、TikTok 和本地上传）的归档均可在详情中暂停视频并「保存当前帧」。选择带「截帧」标识的缩略图后，点击「删除截帧」并确认，只删除这一张截帧，保留原视频、原始图片和其他截帧。删除后同步更新媒体数量、占用空间和 ZIP 内容，默认回到来源视频；若已切换到其他保留媒体，则保持当前选择。删除失败保留原记录与文件，可再次重试。

截帧正在下载或 ZIP 导出、作品正在执行视频编辑时，需等待操作结束后再删除。接口为 `DELETE /api/v1/tools/media-archive/items/:id/frames/:mediaId`，返回更新后的归档；旧小红书命名空间提供相同路径，仅能操作小红书归档。继续沿用管理员、Origin/CSRF 和维护保护，不接受客户端文件路径，不增加数据库迁移。

## 标记已在其他平台发布

所有来源平台的归档卡片、列表及详情弹窗底部均可点击“标记为已发布”，封面底部会出现醒目的绿色“已在其他平台发布”横条。可点击“取消已发布标记”撤销。弹窗与列表共用同一标记，保存成功后同步更新，切换分页、刷新或重启后仍保留。发布状态读取失败时仍可查看媒体，并通过原按钮重试读取。

发布标记与源作品信息、媒体及清单分开保存，不改变作品原始发布时间、归档时间、更新时间、排序和分组；重新获取及配乐编辑不会清除标记。永久删除作品时，在原有删除事务内一并清理其标记，删除失败时一起回滚。旧内容默认未标记，不需要数据库迁移。

`PATCH /api/v1/tools/media-archive/items/:id/publication` 接受 `{ "publishedElsewhere": true | false }`，沿用管理员、Origin/CSRF、维护保护和限流。新列表响应包含可选 `publishedElsewhere`；旧小红书接口及源归档 DTO 不增加此字段。

详情通过同一路径的 `GET` 读取独立发布状态，不受当前列表的分页或筛选限制；读取不修改归档清单、时间或媒体，不创建标记记录。

## 归档列表排序

多媒体归档列表支持按发布时间或归档时间升序、降序排列，默认按归档时间从新到旧。归档时间使用首次成功存档的 `fetchedAt`，不会因翻译、截帧或配乐编辑而变化；发布时间使用平台提供的 `publishedAt`。缺失或无效的发布时间始终排在最后，相同时间按稳定的归档 ID 排列。

排序由服务端在筛选后、分页前执行，适用于全部平台及分组；切换排序会返回第一页并清空当前选择。列表卡片同时显示发布时间及归档时间。`GET /api/v1/tools/media-archive/items` 新增可选 `sort=published-desc|published-asc|archived-desc|archived-asc`；未传排序参数的旧客户端继续使用原先的更新时间排序。翻译批次的筛选范围及旧小红书接口不变。

## 网络与代理

需要 API 所在电脑能访问 TikTok 及其媒体 CDN。代理优先级：

1. `.env` 的 `TIKTOK_HTTPS_PROXY`，示例 `http://127.0.0.1:7897`；设置 `direct` 强制直连。
2. API 进程的 `HTTPS_PROXY` / `https_proxy`，其次 `HTTP_PROXY` / `http_proxy`。
3. Windows 已启用的系统 HTTP 代理。macOS/Linux 不自动读取系统代理。

只接受不含账号、密码和路径的 HTTP(S) 代理。浏览器扩展、PAC、VPN 并不一定提供可用的 HTTP 代理端口。修改设置后重启 API；不改动操作系统代理配置，也不改变其他平台的网络路径。

代理模式通过代理访问固定的 Cloudflare HTTPS DNS 端点，解析目标 A 记录；所有返回地址均须通过既有公网检查，再将 CONNECT 固定到已验证 IP，保留原域名的 TLS 校验和 Host。直连复用现有 DNS 与安全传输。每次重定向继续校验 HTTPS、端口、凭据及公网地址，最多 5 次。没有关闭 SSRF 或 TLS 校验；DNS 失败时不回退到未经验证的代理解析。

Cloudflare DNS JSON 协议见[官方文档](https://developers.cloudflare.com/1.1.1.1/encryption/dns-over-https/make-api-requests/dns-json/)。TikTok 官方提供的[嵌入说明](https://developers.tiktok.com/doc/embed-videos/)说明了公开作品与原作品可见性的关系；本实现不依赖嵌入接口提供媒体文件，而读取公开作品页中返回的数据。

`GET /api/v1/tools/media-archive/runtime/tiktok` 只显示服务就绪/忙碌/关闭，不发起联网探测。任务仍可能因网络、地区、作品可见性或 CDN 拒绝而失败。错误不包含代理凭据或完整媒体签名 URL；失败可手动重试。

## 获取与一致性

- 作品身份由 `tiktok + contentId` 区分；短链最终必须落到受支持的作品页。直接链接重定向后仍须是同一个作品 ID。
- 读取公开页的 SSR JSON，严格匹配作品 ID，不拿推荐作品代替。公开视频的播放、下载及码率候选地址均来自页面本身，不自行生成签名或改写媒体 URL。
- 支持桌面 `webapp.video-detail` 和移动页 `webapp.reflow.video.detail` 的已知结构，以及显式 `playAddr[].src`、`PlayAddrStruct.UrlList`。播放、下载及码率候选的顺序不变，`PlayAddrStruct` 候选最后补充，数组按页面顺序读取；不从封面、字幕或背景音乐中猜测视频地址。
- 部分公开图集页只返回应用外壳；仅在成功公开响应后，尝试同一作品 ID 的普通 `/video/` 页读取 `imagePost`。访问被拒绝时不会进行此回退。
- 页面最大 4 MiB，提取整体超时 60 秒；图集最多 100 张，每项最多 8 个候选地址。媒体继续受原有下载超时、单文件大小、总容量及文件内容检查约束。
- 图集保留顺序且必须完整；视频及页面提供的封面也必须成功保存。媒体失败不提交空归档或不完整结果，刷新失败保留旧归档。
- 成功状态仍在文件和最终记录完成后发布；取消、重启恢复、刷新稳定 ID、翻译归属及选定项删除继续使用原有规则。

## 2026-10-31：商品视频备用解析

部分挂商品链接的视频返回 `isECVideo=1`，但 `playAddr` / `downloadAddr` 均为空；`isAd` 仍可能为 `false`。原生公开页依然优先，仅在作品身份及公开访问检查通过、明确为商品视频且没有视频地址时，使用固定的 TikWM HTTPS 解析接口补充媒体候选。不对登录、私密、删除、验证、身份错误、普通视频或不完整图集启用备用解析；原生已给出的视频地址不被替换。

默认启用，可在 API 的配置 `.env` 或进程环境中设置 `TIKTOK_SHOP_FALLBACK=off` 关闭，重启 API 后生效；`tikwm` 表示启用。此配置同样适用于桌面管理的 API。只允许这两个值，不接受自定义解析地址。页面说明、运行时状态和任务进度会说明备用解析来源。

备用解析会向 TikWM 发送去除分享参数及锚点后的公开作品链接，不发送 Cookie、登录资料、代理凭据或本地数据。请求复用 TikTok 的网络/代理及公网 DNS、TLS、重定向安全检查。备用请求串行执行，起始间隔至少 1.1 秒；单次请求最长 20 秒，响应最多 1 MiB，仍受原有提取总超时和取消控制。服务故障或限流会明确报错，不无限重试；第三方服务的长期可用性不能保证。

结果必须返回完全一致的字符串作品 ID；只接受原有 TikTok/CDN 域名规则允许的 HTTPS 视频地址。标题、正文、作者、话题、发布时间及封面继续来自 TikTok 原始公开页。媒体下载继续沿用容量、摘要、文件提交、分组、去重及主页任务结果回填；备用视频额外检查 MP4 中的视频轨道，拒绝将纯音频文件作为视频归档。无需新增模型、Python 依赖或修改能力包。

## 数据库兼容

Schema v7 扩展归档表的平台 CHECK 约束。启动前使用现有备份机制生成 `schema-v7-*` 升级前快照，事务内重建该表并复制原始列值；保留原始 JSON、子记录、索引及触发器。升级期间暂时禁用外键级联，提交前检查所有外键，正常运行重新启用外键。失败回滚整个事务。

历史 Schema v6 备份仍可通过原有恢复工具使用。旧代码不能直接读取 v7 数据库；若要回退，先停止服务、完整备份当前数据库与媒体，再恢复匹配的升级前快照。恢复会撤销备份之后的数据库修改。迁移及故障验证使用隔离临时库；未执行用户历史数据清理或手动恢复命令。开启自动重载的开发服务也可能在源码更新后触发正常启动升级，可在原有迁移备份目录核对记录。
