# 按模块数据导出与导入实施方案

状态：DBK-00～DBK-05 的功能代码，以及 DBK-06 的自动化回归、普通构建和分发夹具已完成；实现、检查结果和既存失败见 [数据备份与恢复](module-data-backup.md)。安装包、跨设备真实体量及 macOS 仍待实机验收，不以源码检查代替。

核对日期：2026-10-30。代码基线：`cb99350` 加当前工作区修改。实施前必须重新核对 Git 状态，保留已有的发布标记等未提交修改。

已确认：同时支持「合并导入」和「替换所选模块」；其他未选模块的数据必须保留。允许一次选择一个、多个或全部业务模块。

## 1. 产品入口与首版边界

在桌面设置增加「数据备份与恢复」入口，打开 `/settings/data-backup`。这是系统管理小模块，不新增第七个业务工具入口。

页面分为「导出数据」「导入数据」两部分，底部显示最近操作、结果和失败重试入口。列表有分页时必须显示总条数。尽量在一个页面内完成，不拆成大量独立设置页。

首版完成 Windows 桌面端六个业务模块的导出和两种导入方式。备份协议采用平台无关的业务格式，但 macOS 恢复仍需独立验收，不能用协议设计代替实机兼容结论。源码 Web 本机入口留作后续接入，不在首版冒称已经支持；LAN 访客不获得备份或恢复系统数据的权限。

导出与导入的是应用管理的业务数据及明确选择的本机模块偏好，不是安装程序、开发环境或整机镜像。

## 2. 导出范围与模块归属

“模块全部数据”指快照时仍存在的受管业务记录、有效文件及其关联数据。不能恢复已经永久删除、已经清理的文件，不能到用户其他目录搜索未留存的原文件，也不包含未保存的编辑草稿。

| 可选模块       | 必须覆盖的内容                                                                                                                                                 | 特别说明                                                                                 |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| 图片压缩       | 受管任务、仍存在的压缩结果、对应文件记录                                                                                                                       | 通用 `tasks`、`outputs` 并非压缩独占；按任务归属取数据。原图未保存到应用时不承诺导出原图 |
| AI 图片处理    | 各处理类型的任务、输入、蒙版、结果、商品图配方和独立素材快照、历史记录                                                                                         | 导入后改写受管文件位置，不保留源设备绝对路径；不能重新引用已经删除的源结果               |
| 多国语言配音   | Edge-TTS 和 Chatterbox 的单条任务、批次、片段、文案、翻译、参数、音频、字幕、参考音色及其授权记录                                                              | UI 作为一个模块选择，内部按两个引擎适配；永久参考音色不能按批次临时文件处理              |
| 音频素材库     | 全部素材、背景音乐、分组、文案、备注、回收站、播放预设及独立音频文件                                                                                           | 保持现有 ZIP 备份/恢复入口及原合并规则兼容                                               |
| 多媒体内容归档 | 四种来源的作品、原文/译文及人工修订、媒体/封面/截帧、原片/最新成品、配乐和水印快照、配方、作品分组/成员、发布标记、水印库/轨迹预设、表格批次及 TikTok 主页历史 | 模型与平台浏览器会话不属于作品数据；后台获取/翻译/视频编辑的历史记录按模块归属导出       |
| 局域网文件传输 | 完成上传的文件、图文便笺及图片、下载统计、创建/到期时间等业务记录                                                                                              | 不包含未完成分片、断点上传令牌、临时访问凭证                                             |

第一阶段建立精确的所有权清单，列明每个模块对应的：

- 数据库领域表、`entities.kind`、通用 `tasks.toolId` 与文件索引归属。
- 受管目录、受管文件、持久化 JSON 清单及 `domain_state` 初始化标记。
- 强关联、来源说明、跨模块独立副本，以及需要重建的内存索引。
- 绝对路径、相对路径、媒体 URL、校验摘要和版本字段的处理方式。

不能只复制六个目录。当前数据库中既有专表，也有 `entities` 中的领域记录；不能复制整张 `entities`、`tasks` 或 `files` 表来实现某个模块的恢复。无法分类的记录必须登记，不能悄悄归入某个模块或丢弃。

### 本机偏好

增加「包含本机模块偏好」选项，仅导出白名单中的本客户端状态，例如归档卡片/列表模式、音频库筛选与播放队列。按导入后的 ID 映射恢复分组和队列引用，播放器恢复为暂停，不能自动开始播放。

这不等于收集所有浏览器数据：不导出任意 localStorage/IndexedDB、其他浏览器的状态、LAN 访问设备的偏好或未保存页面草稿。与 API 地址绑定的偏好键在目标设备重新生成，不复制旧端口或旧主机地址。

### 明确不放入业务备份包的内容

- Node/Python/FFmpeg、已安装能力环境、模型权重和可重建依赖。
- 浏览器登录状态、Cookie、账号凭据、会话令牌、管理员 PIN、签名私钥及原始 `.env`。
- 日志、一般缓存、上传分片、安装暂存、旧迁移包和本次操作的中间文件。
- 正在运行的进程、SSE 连接、未完成的任务执行现场和前端 File 对象。

备份包可记录所需能力 ID/版本作为提示，但不视为已安装。缺少能力时仍可导入、浏览和下载历史成果；新的生成任务遵循现有能力安装规则。

## 3. 两种导入方式

### 3.1 合并导入：默认方式

目标是添加缺少的数据，并保留目标设备已有内容。默认不覆盖目标设备对同一内容的编辑、分组、发布标记和到期时间。预检先给出「新增、跳过、冲突、需重新编号、无法恢复」的具体数量及原因。

| 对象                   | 合并规则                                                                                                                                                         |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 多媒体作品             | 以 `platform + contentId` 为真实身份。同一作品已经存在时保留目标整条归档及其编辑版本，不用新 ID 绕过数据库唯一约束；导入历史中对此作品的引用映射到目标的真实作品 |
| 任务、片段、参考音色等 | 身份、元数据和文件完全相同的记录跳过；仅 ID 碰撞而内容不同的，给导入对象生成符合原领域限制的新 ID，并重写其完整关联，不覆盖目标记录                              |
| 音频素材库             | 复用现有规则：同 ID/摘要跳过，ID 冲突生成新 ID，同完整分组路径复用；保留回收站和预设的现有恢复语义                                                               |
| 作品分组               | 按本领域的名称比较规则复用同名分组，否则新增；不将原分组错误映射到其他设备的同 ID 分组                                                                           |
| 水印素材/轨迹预设      | 素材按本领域已实现的规范化摘要判重；预设需比较实际方案，名称冲突以明确的导入后缀处理，不覆盖目标方案                                                             |
| LAN 文件/便笺          | 明确相同记录才跳过；ID 碰撞重新编号。不能仅按文件名或文本相同就合并不同用户记录                                                                                  |

不对所有模块强行应用“同 SHA-256 就是一条记录”：同一文件可能有不同文案、授权、分组和历史含义。去重依照各领域现有语义。

预检中的 ID 映射以「模块 + 实体种类 + 原 ID」为键，不能只用一个全局字符串替换表。必须覆盖数据库父子关系、清单、文件位置、媒体 URL、批次引用、素材来源和本机播放队列。强关联缺失时阻止导入；来源说明等弱关联不应误指向目标设备同 ID 的无关对象。

重复导入不能只依靠每次随机生成的新 ID。恢复操作应持久记录「备份 ID + 清单摘要 + 模块 + 实体种类 + 原 ID」到目标实体的映射及内容指纹，并与本次数据提交保持一致。再次导入时，同时核验回执和目标实际记录/文件：仍然一致才跳过；已经删除或修改的对象重新进入预检，不能仅凭旧回执判定已恢复。回执按模块管理，替换或回滚时同步处理；它属于恢复工具的管理记录，不应污染用户业务字段或沿用其他设备的目标映射。

合并不会升级成隐式覆盖。需要将某个模块完全恢复到备份状态时，应使用替换方式。

### 3.2 替换所选模块

先自动保存所选模块在目标设备的完整恢复备份，再将这些模块恢复到包内状态。未选模块的记录、文件和配置不变。

- 包内为空、目标非空的模块，预览必须明确显示“将清空该模块的现有业务数据”；不能把空模块当作未选择模块。
- 对数据库只替换登记的模块记录集合，不覆盖整份 `toolbox.db`。
- 即使是替换模式，也要检测与未选模块共享表中的 ID 碰撞，例如通用任务 ID；必要时映射导入 ID，不能覆盖其他模块任务。
- 预览列出当前数量、备份数量、替换范围、自动备份位置和空间需求；用户确认后执行。
- 多选模块作为一组提交。首版不接受只成功替换其中一部分、却把整次恢复标记为成功。

### 跨模块关系

多媒体归档的已保存配乐、水印和成品使用独立副本。只导出归档模块，也必须能够播放成品、恢复原片和继续使用已保存的配乐/水印，不要求顺带导入整个音乐库。

音频素材库已归档音频同样保持独立副本，不要求对应配音任务仍存在。引用来源任务的说明不等于运行时依赖。

若审查发现某条实际强依赖尚无独立副本，导出预检应明确列出并纳入必要依赖，或阻止生成不完整备份；不得隐藏地导入或替换另一个整模块。

## 4. 导出、预检和恢复流程

### 导出

1. 选择模块以及是否包含本机模块偏好，统计记录、文件和字节。
2. 检查活动任务、编辑提交、下载/导出占用和播放；给出具体阻挡，不擅自结束任务。
3. 用户选择保存位置。桌面主进程取得文件句柄/受控选择令牌，渲染页面不提交任意系统路径。
4. 进入维护流程，正常停止后台服务，生成一致的只读业务快照并校验引用文件。
5. 快照复制完成后恢复服务，再从独立快照流式生成 ZIP。快照不得采用无法证明不可变的硬链接替代。
6. 备份完全写入、校验成功后，将目标 `.partial` 文件改为最终名称，才显示完成。

首版允许在快照阶段暂时停止整台客户端的后台服务，不承诺其他模块此时仍可提交任务；未选模块的数据内容不得因此发生变化。进度由桌面 IPC 提供，不能依赖已经停止的 API/SSE 服务。

文件缺失或损坏时，默认不生成被称为“完整”的备份。展示所属记录及原因，保留诊断信息；不能静默跳过素材然后报成功。

### 导入预检

选择备份文件 → 验证包格式与版本 → 显示包内模块 → 选择要恢复的模块 → 选择合并或替换 → 检查目标数据与冲突 → 显示完整预览。

预检不修改业务数据，返回有期限的恢复计划和目标数据指纹。预检后发生新任务、改组、删除或编辑时，提交前必须重新核验；计划过期则重新预检，不能按过时统计直接覆盖。

### 正式恢复

1. 取得维护互斥，正常停止服务，再次核对预检计划。
2. 为所选模块保存导入前恢复点；合并也保存恢复点，便于撤销整次添加。
3. 在每个目标目录所在磁盘的受控暂存区准备最终文件，验证摘要、容量和全部 ID 引用。
4. 按恢复计划切换所选目录，并通过一个 SQLite 事务提交所选记录、关联和文件索引。
5. 写入持久化提交状态，重新启动服务，检查模块读取及媒体可用性，再向 UI 发布成功。
6. 如未完成提交，按恢复日志回滚；如已完成提交但启动失败，保留恢复点及诊断，不显示成功或让用户反复覆盖重试。

文件系统和 SQLite 不是同一个原子事务。必须实现持久化恢复日志及启动前恢复机制，区分 prepared、files-switching、database-committed、verified 等阶段，不能只依赖 try/catch。

磁盘不同的目标目录分别在同盘暂存，不能假设任意位置都能用 rename 原子移动。快照、备份和最终文件的空间都需计入预检；不足时在修改业务数据之前停止。

### 回滚与取消

- 校验、复制和打包阶段允许取消并清理本次暂存；提交切换阶段进入“正在安全收尾”，不能中途强行退出而留下半套数据。
- 恢复日志在应用启动业务服务前处理，避免自动清理或旧内存索引先接管中间状态。
- 后续手动回滚也是一次按模块恢复：明确说明本模块导入之后的新变化将被替换，并先备份现状。不能恢复整库旧副本而抹掉其他模块的新数据。
- 自动恢复点单独列出并统计体积，支持显式删除；首版不自动按天清除这些恢复点。

## 5. 备份文件格式

建议使用普通 ZIP/ZIP64，扩展名 `.zip`，不引入自定义加密容器或新的压缩依赖。复用项目现有 `archiver`、`yauzl` 和 Node 流式 IO。

```text
manifest.json
modules/
  content-archive/
    records.json
    files.json
    preferences.json       # 仅在明确包含本机偏好时存在
  audio-library/
    records.json
    files.json
objects/
  <sha256>                 # 包内文件内容，相同摘要可只保存一次
```

包内去重不改变恢复后的领域文件归属；两个模块需要独立文件时仍分别恢复，不能因此引入共享删除风险。

顶层 manifest 至少包含备份协议版本、各模块数据版本、创建时间、来源应用版本、备份 ID、模块清单、记录/文件数量、字节数、各元数据文件摘要，以及依赖和保留期提示。数据库版本仅作为兼容信息，不携带可直接执行的 SQL。

`files.json` 将受控逻辑位置映射到包内对象、大小和摘要；不保存源设备绝对路径。原始文件名仅作为业务元数据，不直接作为任意落盘路径。图片/音频/视频等已压缩资源优先原样存储，避免长时间无效压缩；JSON 可压缩。支持超过 4 GiB 和超过传统 ZIP 条目上限的备份。

完整性校验不能等同于可信来源签名。此功能不读取或复用能力包签名私钥，不重新签名任何能力包。

## 6. 保留规则、历史兼容与安全

- 保留原创建时间、归档时间、内容发布时间、授权记录和有效的业务字段，不用导入时间重写这些时间。
- 配音批次、LAN 文件和无成功结果任务的到期时间保持原规则。预检明确列出已经到期的记录及启动后可能清理的数量，不能把它们悄悄改成永久保存。
- AI 图片成功结果、音频库永久素材、作品归档等继续遵循各自的长期保留规则。
- 模块存在活动任务或未完成提交时阻止对应快照；不把进行中任务带到新设备自动继续，也不自动发起模型生成、平台获取或浏览器登录。
- 已有音频库 ZIP 恢复和旧版数据目录迁移继续保留原语义。新模块不重写旧接口，也不能把旧音频库 ZIP 误判成完整应用备份。
- 导入器按协议及模块版本判断兼容性，而不是仅比较应用版本字符串。明确不支持的新格式在修改目标前拒绝。
- 严格拒绝目录穿越、绝对路径、盘符、UNC、符号链接、重复/大小写碰撞条目、未登记对象、无效摘要和解压预算超限；不执行包内代码、脚本或 SQL。
- 按实际未压缩大小、元数据预算、文件数及剩余磁盘空间设置上限；不要沿用普通上传的 2 MiB、500 MiB 限制，也不能无上限解压。
- 所选模块的正常配额、音色数量、预设数量和分组约束仍执行；超限在预检明确拒绝，不能导入一半后静默丢掉剩余数据。
- 本机只开放固定的备份/恢复能力。远程 LAN 页面不能通过伪造 API/IPC 调用进行整模块替换或读取本机任意目录。

## 7. 实现结构与复用点

按当前 monorepo 结构落地，避免为每一步建立只有一次调用的薄壳文件。

```text
packages/shared/src/system/data-backup.ts
  协议、模块 ID、预检/进度/结果 DTO 与 Schema

apps/api/src/system/data-backup/
  service.ts               # 统一编排与恢复计划
  registry.ts              # 六模块所有权及领域适配器登记
  package-io.ts            # ZIP64、清单、流、摘要及路径校验
  restore.ts               # 暂存、数据库提交和持久恢复日志
  merge.ts                 # 冲突决策、回执、配额及合并计划
  references.ts            # 按类型改写 ID、文件位置和媒体 URL
  validation.ts            # 复用领域格式校验；适配器集中于 registry，不引入六套状态机

apps/api/src/data-backup-entry.ts
  后台服务停止期间可运行的受控 Node helper

apps/desktop/src/data/data-backup.ts
  文件对话框选择、维护互斥、helper 生命周期和启动恢复
apps/desktop/src/ipc/data-backup.ts
  逐方法注册受控能力，不暴露任意路径/进程操作

apps/web/src/features/data-backup/
  page.vue                 # 导出、导入预览、进度与结果
  useDataBackup.ts         # 该页面完整状态和生命周期
```

数据库仍通过既有 façade 和明确领域适配器处理。既有音频库合并规则、文件摘要网关、原子文件提交、桌面正常停止/重启和退出保护应复用；不能把不同领域的 Repository、队列、保留期合并成万能框架。

helper 必须加入正常 tsup 构建和桌面资源布局，使用新源码位置但保留 `resources/backend` 的分发映射。桌面不直接导入 API 内部源码，也不复制整套源码到安装产物中。

preload 只暴露固定方法，例如列出模块、选择备份、预检、开始导出/恢复、取消和读取进度；文件选择使用短期令牌。业务模块未启动时，helper 仍能只读扫描和恢复，但不能因导出而触发数据库升级、业务清理或旧任务重生成。

导入后需要重新建立各模块内存索引，因此首版采用正常重启后台服务。重启后返回备份页面并显示持久化结果，不能只跳回首页丢失操作结论。进度通过 IPC 区分扫描、校验、复制、写记录、压缩、启动验证，各阶段展示真实的文件/记录数量和字节进度。

## 8. 分阶段交付与验证

每阶段开始检查工作区，保留已有修改；不自动提交、推送、发布、构建桌面安装器或修改签名能力包。

| 阶段   | 工作                                                         | 验收门槛                                                                                             |
| ------ | ------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------- |
| DBK-00 | 固化六模块数据所有权、跨模块依赖、冲突策略、格式和样本       | 每类数据都有归属；现存持久字段/文件没有未经说明的排除；使用合成文件和临时数据库                      |
| DBK-01 | 包格式、helper、维护互斥、版本/路径/摘要校验、预检和恢复日志 | 合法/损坏/恶意 ZIP、ZIP64、取消、磁盘不足和断电阶段恢复测试；不接真实业务数据                        |
| DBK-02 | 音频素材库与多媒体归档适配，两种导入方式均实现               | 音乐/水印独立快照、分组/发布标记/预设、同作品冲突及重复导入测试；保留旧备份入口                      |
| DBK-03 | AI 图片、多国语言配音、图片压缩适配                          | 原图/蒙版/配方、CPU/GPU 元数据、参考音色授权、字幕/批次/片段、路径改写及到期规则测试；不启动真实模型 |
| DBK-04 | LAN 文件/图文、本机偏好和全部模块组合                        | 不导入分片令牌；保留到期时间；播放暂停恢复；所有模块组合与未选模块隔离测试                           |
| DBK-05 | 页面、文件选择、进度、重试、自动恢复点和手动回滚             | 六个模块均可单选/多选；来源与目标预览清晰；读写失败和连续操作不污染其他设备数据；分页显示总数        |
| DBK-06 | 全量回归、真实体量与文档验收                                 | 六模块分别导出并恢复、合并/替换/回滚、普通构建和桌面编译/分发夹具通过；安装器和 macOS 实机另列验收   |

DBK-02 的两个模块先用于验证架构，不等于功能整体完成。必须完成 DBK-04 后才能将六模块全部开放，未接入模块不得出现可点击但实际不工作的入口。

### 强制回归样本

1. 空设备恢复一个模块、从多模块包只恢复一个模块、全部模块恢复。
2. 目标已有数据时的合并、同 ID 不同内容、同作品不同编辑、同名分组/预设。
3. 同一备份重复导入的确定性；所有跳过、重新编号和冲突结果可解释。
4. 替换前后其他模块的数据库业务载荷、文件摘要和可访问结果一致；不通过比较整份 DB 文件字节误判正常 SQLite 变化。
5. 只恢复归档仍能使用已有视频成品、配乐和水印；只恢复音频库不依赖源配音批次。
6. 导入后源设备路径不可访问，所有媒体仍可预览/下载，ID 引用和文件索引正确。
7. 中文、空格、不同磁盘、只读目标、容量不足、超过 4 GiB、文件缺失或损坏。
8. 每个文件切换及数据库提交阶段注入失败，验证恢复日志、回滚和再次启动；失败不误报成功。
9. 播放、生成、上传、删除、清理、升级和退出与维护流程互斥，不结束无关进程。
10. 原有 TTL、永久留档、回收站及删除规则不变；导入不自动重新生成或重新登录。
11. 本机偏好按目标地址和 ID 映射恢复，旧客户端和其他 LAN 客户端的数据不被全量读取或改写。
12. 普通构建产物包含 helper，隔离分发目录中也能完成导出、预检和恢复。

每阶段执行定向测试、类型检查、Lint、格式、架构边界及 `git diff --check`；共享提交基础和最终阶段执行全量回归与普通构建。禁止通过扩大超时、删除测试、降低覆盖率或提高分包预算掩盖问题。

最终交付包括：可用的六模块备份页面、版本化备份格式、两种恢复策略、预检与报告、自动保护备份/手动回滚、故障恢复测试及使用文档。只有这些全部通过验收，才称为支持按模块导出和导入。
