# 音频提取器

入口：侧栏“音频提取器”，页面 `/tools/audio-extract`。从本机选择 MP4、MKV、AVI、MOV、WebM 视频，生成独立音频；原视频不会修改、移动或删除。浏览器通过本机或可信局域网服务处理，不上传到外部解析服务。

## 使用

1. 选择输出方式：MP3（默认 192 kbps，可选 128/256/320）或保留原音轨。提高码率不能恢复已经丢失的细节。
2. 选择默认音轨、全部音轨或多音轨时手动选择。默认音轨优先使用文件的默认标记，否则使用第一条；手动模式在识别后确认语言和轨道，再继续。
3. 一次选择最多 1000 个视频并开始。每个视频上传、识别和处理完成后再接收下一个，最多同时暂存两份输入，不会一次上传所有视频。单个最大 2 GiB、最长 6 小时，最多 32 条音轨；超限会明确失败，不截断后伪装成功。
4. 在提取记录中试听、单独下载或多选下载 ZIP。分页显示总条数，支持本页全选、逐条勾选和跨页保留选择，单次最多选择 1000 条成功结果。试听复用音频素材库的真实波形，支持定位、播放/暂停和音量调整；超过 1 小时或 100 MiB 的结果使用进度条试听。

实际兼容性由文件内容及 FFmpeg 编解码支持决定。浏览器无法直接播放某些原音轨时仍可下载。提取保留原有音轨中的人声、音乐及环境声，不做人声分离。保留原音轨不会重新编码，也不静默转换为 MP3。AAC/ALAC 使用 M4A、MP3 使用 MP3、FLAC 使用 FLAC、Opus/Vorbis 使用 OGG、支持的 PCM 使用 WAV、AC3/EAC3/DTS/MP2 使用 MKA；其他原编码提示改选 MP3。

## 队列、去重及保留

- 相同视频 SHA256、相同音轨及相同输出参数复用进行中或完整有效的成功结果。原编码模式不将无效的 MP3 码率选项纳入去重键。更换音轨、输出方式或 MP3 码率生成新任务；缺失或损坏的结果不会阻止重试。
- 成功结果和记录长期保留，手动删除。该模块结果及空间预留上限 20 GiB，输入/输出接收前检查磁盘。限制集中在共享契约和领域服务内，不扩大其他模块的上传限制。
- 未提交的识别输入有效期为 2 小时；已提交且仍活跃的输入不会因该有效期删除。任务结束后清理临时视频副本。取消会等待受控 FFmpeg 子进程结束，不发布半成品。
- 停止后续上传不会取消已经接收的任务。关闭页面后已提交任务继续，尚未上传文件不会持久化。程序退出后中断任务不自动重跑；重新选择原视频重试。
- 文件校验、原子提交及数据库终态完成后才发布成功。删除正在提取、播放传输或加入素材库的结果会被拒绝；批量删除逐条执行，失败项保留选择用于重试。
- 普通缓存清理不包含永久提取结果。删除操作只作用于该模块拥有的路径，原始本机视频始终保留。

## 音频素材库

支持单条或多选加入，选择用途和目标分组。已有相同音频按素材库现有规则复用；回收站中的音频需先恢复。素材库实际接收 MP3、PCM WAV、AAC M4A、FLAC，单条最大 100 MiB，原有容量/回收站规则不变。

不兼容的 OGG/MKA/ALAC 等结果可勾选“生成 MP3 副本后加入”，明确以 192 kbps 生成独立 MP3。转换失败不影响原提取结果。超过素材库上限时提示，仍可下载。删除提取记录不会影响已加入的独立素材；删除素材也不会删除提取记录。

## 存储、备份与运行时

数据库 kind/tool ID 为 `audio-extract-job` / `audio-extract`；结果存于 `<storageRoot>/audio-extract/results/<jobId>/audio.<extension>`，临时输入只位于同模块 `staging`。冲突导入兼容现有备份生成的 ID，不改变既有合并/替换规则。

桌面设置的“数据备份与恢复”可单独选择音频提取器，包含任务记录和有效结果；支持合并、替换和恢复点，保留未选模块。临时视频、未完成任务、模型和运行环境不随备份迁移。

复用现有 FFmpeg 共享媒体运行时；桌面受管模式不回退系统环境，源码模式沿用配置的 FFmpeg/FFprobe 路径。没有新增模型、Python 依赖、下载服务或签名能力包。业务入口通过现有 LAN 工具白名单自动开放；系统管理权限仍仅限本机。

验证使用隔离临时目录和合成视频；涉及五种容器、多音轨、原编码音频包摘要、取消、文件提交失败、去重、Range、ZIP、素材库副本以及备份合并/替换。不以合成测试代替所有真实编码或安装包验收。
