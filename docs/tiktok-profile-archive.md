# TikTok 主页批量归档

入口：多媒体内容归档 → **TikTok 主页批量归档**。支持输入 `https://www.tiktok.com/@用户名`，分享参数会从主页地址中去除。单条作品入口及 Excel/CSV 导入的输入规则保持不变。

## 准备与使用

1. 自动读取方式需安装现有的“归档浏览器 / Chromium”能力。此入口复用已签名的浏览器，只读取其安装资产，不修改或重建能力包，不自动下载新依赖；单条 TikTok 归档和下文的普通浏览器助手不需要该浏览器能力。
2. 确保运行 API 的电脑能访问 TikTok。代理沿用已有 `TIKTOK_HTTPS_PROXY`、进程 HTTP(S) 代理、Windows 系统 HTTP 代理的优先级。修改配置后重启服务。
3. 输入主页，点击“读取主页作品”。运行服务的电脑上会打开独立 TikTok 浏览器；LAN 客户端需要在服务所在电脑上操作该窗口。
4. 如果平台显示登录、验证、隐私选择或网络提示，请在独立浏览器中正常处理。程序不代填凭据、不跳过验证，不读取或复用其他浏览器、小红书、抖音的登录状态。浏览器会话不写入任务数据库，浏览器结束后丢弃。
5. 核对发现数量、主页统计和完整性提示。发现列表只保存链接和公开元数据，**尚未下载或归档媒体**。
6. 选择“全部已发现作品”或跨页勾选作品，选择已有归档处理方式和可选目标组，再确认开始。列表未确认完整时，必须明确勾选仅归档当前已发现部分。
7. 后台自动以每批最多 100 条依次提交现有归档服务；上一批结束后再提交下一批。沿用原队列并发、两次成功入队至少间隔 7 秒、媒体配额、原子提交、翻译及截帧规则。
8. 可以关闭弹窗；后端运行时继续执行。可重新打开历史任务查看进度、作品结果、已归档详情或导出 CSV。服务退出后不自动续抓，需手动继续未完成/失败项。

## 完整性与停止

当前限制：自动窗口已出现“曾读取 96 条，但重新打开仍返回空响应”的情况，最新启动参数并不能保证稳定读取。普通浏览器和无痕窗口可显示视频，并不代表自动窗口能取得同样数据。此问题尚未彻底解决；不要把此前两次成功当作稳定性验收。下面的普通浏览器采集助手是可选补充方式，未替换原自动入口。

- “列表完整”必须来自从游标 `0` 连续到最终 `hasMore=false` 的正常浏览器分页响应，响应所属账号须与主页匹配。DOM 链接、滚动停止、相同游标循环或作品数碰巧一致都不能作为完成证明。
- 若发现数量低于主页提供的作品统计，即使读到分页末尾也保守标为未完整。主页统计本身不保证每条内容当前可见；私密、已删除、地区/年龄限制或平台拒绝的作品不能保证获取。
- 空内容、非 JSON 分页、登录或验证提示不会被当作“该用户没有作品”。平台限流、身份不一致、数量上限、超时及用户关窗都会保留已发现进度并报告未完整。
- 每次发现最长 10 分钟；非交互状态连续 30 秒没有后续数据时保留部分结果。每个主页任务最多保留 10000 条作品；达到上限不报告完整。
- “继续读取 / 检查新作品”重新从主页正常加载，保留并去重之前发现的链接；不重放旧会话的请求签名或伪造分页接口。当前一轮的分页完整性重新验证，不拿旧列表数量替代。
- 停止发现会关闭本任务的浏览器，保留链接。停止归档会停止尚未提交的批次，并取消本任务拥有的待执行子任务；已在处理/原子提交中的作品按原规则结束。其他手动归档不受影响。
- 某个作品失败不会阻断后续作品。手动重试只包含失败或程序中断后未完成的项目，已成功及已跳过项目不重复提交。主动取消项可重新选择后明确开始。
- 默认跳过已有归档。目标组只应用于本次获取或刷新成功的作品，已跳过作品保持原组；目标组删除后不会被后台重建。

## 普通浏览器采集助手

入口：主页批量弹窗 → **自动窗口仍然出错？使用普通浏览器采集**。这是当普通浏览器可见、自动窗口空白时的可选方式，不需要提供账户、Cookie 或安装扩展。

1. 先手动停止当前自动读取；助手不会替用户停止或删除任务。
2. 点击“下载普通浏览器采集助手”，打开下载的 HTML。按 Ctrl+Shift+B（Mac 为 ⌘+Shift+B）显示书签栏，将蓝色“采集 TikTok 作品”链接拖到书签栏。也可复制采集书签地址，粘贴到新建书签的网址中。
3. 在您能正常查看视频的普通浏览器中打开 TikTok 用户主页，点击采集书签，再点击面板里的“开始采集”。保持页面在前台；加载由 TikTok 自己的页面完成。遇到可见弹窗或验证会停止滚动，由用户正常处理后手动继续。
4. 点击“停止并准备 CSV”，逐份下载 CSV（每份最多 100 条）。超过 100 条会显示多个下载链接，不自动连续下载文件。
5. 返回项目的“表格批量归档”，导入 CSV、核对预览、选择分组及已有作品处理方式，确认后归档。复用原有队列、跳过已有作品、配额、限流、媒体提交和删除机制。

助手仅在 HTTPS TikTok 主页运行，只接受同一用户名的规范作品链接，按作品 ID 去重并移除分享参数，最多 10000 条。切换到其他主页时停止；后台暂停滚动；最长运行 10 分钟，连续 30 秒无新增链接时准备已发现结果。所有结果始终标记为“列表未确认完整”，不把滚动停止当作全量证明。

助手只补充作品链接。若已有作品链接在归档时报告 `TIKTOK_MEDIA_INVALID` 等媒体地址错误，此助手不能修复视频解析或下载；需要继续排查单条作品返回的数据。

助手不构造或重放平台 API 请求，不读取 Cookie、登录资料、本机文件或存储，不向工具箱后台自动上传。生成的 UTF-8 BOM CSV 仅含“作品链接、平台”两列。发现列表暂存于当前页面内存，关闭助手或刷新页面会丢弃未导出链接；已下载 CSV 由用户保留。CSV 进入现有导入流程后按原规则保存批次和媒体，不写入自动主页任务的进度记录。

此方式的生成、压缩产物独立执行、CSV 下载和真实导入预览已通过受控测试；用户实际主页的全部 616 条及浏览器书签策略仍需实测。平台本身的不可见、登录或访问限制仍会影响采集。

## 数据与历史记录

主页任务写入现有 SQLite `entities` 表的 `tiktok-profile-job` kind，使用版本化记录保存作品发现、选择及所属批次 ID。不新增数据库迁移，不改变归档、媒体、模型目录及数据保留规则。数据库备份包含这些记录；只备份媒体目录不包含发现进度。

最多保留 20 个主页任务和现有的 100 个归档批次历史；没有新增自动删除规则。批次历史满时任务停止并给出原因，先手动整理历史再继续。每个主页任务最多创建 1000 个批次（包括手动重新尝试）；达到上限可新建主页任务。

子批次及主页归属在同一个数据库事务中保存，归属记录失败不会开始无主下载。主页记录存在时，所属批次仍由主页协调器管理，避免丢失进度和重复调度；停止所属批次也会停止主页后续归档。表格窗口明确显示所属主页，并提供“打开所属主页任务”“停止主页任务”和“清理所属主页任务记录”，无需手动判断删除顺序。失败重试直接进入对应主页任务。

按 2026-10-27 的界面简化要求，删除主页任务记录会同时清理其全部归档批次记录；确认框明确显示此范围。主页及子批次元数据在同一数据库事务中删除，失败则全部回滚，内存状态也在提交成功后更新。已归档作品、媒体、译文、截帧和分组保留，其他主页和手工导入批次不受影响。活跃主页或子批次必须先安全停止；可直接在表格窗口停止所属主页任务并等待当前作品结束。旧版本留下的无主页归属记录批次仍可单独管理。没有新增自动清理或数据库迁移，普通作品删除及刷新取消保护继续复用原实现。

表格批次历史改为可搜索、可收起的卡片列表，分别展示完整来源名称、创建时间、状态和来源类型。作品结果表格为平台、状态及进度设置独立列宽，避免 TikTok 和“已跳过”等文字挤成竖排；小窗口可横向滚动查看全部结果列。本轮按用户要求不进行截图验证。

## 失败作品逐条重试与单条获取

失败行的“重试”只重新提交该作品，保留主页任务的已有归档处理方式及有效分组。主页仍在归档时，该作品加入后续队列，不中断当前批次，也不重复提交其他作品；等待重试的行不再显示重试按钮。停止任务仍会停止后续重试。

点击作品标题会关闭主页弹窗，将该链接和 TikTok 平台填入主页面的“获取并存档”入口；由用户点击按钮提交，不自动替换或取消正在运行的任务。Ctrl / Command 等修饰点击仍可打开原作品。

普通入口成功完成文件及记录提交后，服务按 TikTok 平台与作品 ID 匹配主页任务中的失败记录，不按标题或用户名猜测。重新打开主页任务即可查看成功状态、100% 进度、查看存档及同步后的计数，CSV 同样使用同步结果。匹配关系保存在主页任务记录中，不改写原导入批次，任务历史裁剪及重启后仍可读取；删除归档后不再显示该匹配。之前已有的成功不会掩盖一次较新的刷新失败，正在排队或运行的刷新也不会提前显示成功。原数据保留和删除规则不变。

`POST /:id/retry` 不带正文时仍继续全部失败及未完成项；可选正文 `{ "itemId": "作品数字ID" }` 用于逐条重试，仍沿用管理员、Origin、维护保护和限流。

## 安全与生命周期

浏览器使用独立非持久上下文、禁止文件下载和外站顶层导航，并通过既有本机鉴权 HTTPS 隧道访问网络。每个目标地址均经公网检查，连接固定到同一次校验的 IP；配置上游代理时，对已验证 IP 做 CONNECT，保留浏览器原始 TLS Host/SNI。不会降级到未经验证的代理 DNS 或关闭 TLS 校验。

发现、等待用户操作、归档和安全停止状态都计入现有维护/退出保护，防止批次间隙误执行深检、能力卸载或数据迁移。浏览器、计时器、响应监听和关闭流程由本任务拥有，不关闭其他浏览器或应用进程。

## API

基础路径 `/api/v1/tools/media-archive/tiktok-profiles`。写请求沿用原管理员会话、精确 Origin/CSRF、维护互斥、参数校验和限流；不接受 Cookie、密码、任意浏览器路径或 API 签名。

| 方法   | 路径                | 说明                                                                                                           |
| ------ | ------------------- | -------------------------------------------------------------------------------------------------------------- |
| GET    | `/`                 | 最近主页任务，最多 20 个，仅摘要                                                                               |
| POST   | `/`                 | `{ url }` 创建发现任务，不开始归档                                                                             |
| GET    | `/:id`              | 摘要、完整性及归档计数                                                                                         |
| GET    | `/:id/works?page=1` | 作品及最新结果，每页 50 条，最多 200 页                                                                        |
| POST   | `/:id/discover`     | 正常重新读取主页、去重并补充作品                                                                               |
| POST   | `/:id/archive`      | `{ selection: "all" \| "selected", itemIds?, existing: "skip" \| "refresh", groupId?, allowPartial: boolean }` |
| POST   | `/:id/cancel`       | 停止后续发现或归档，安全完成当前提交                                                                           |
| POST   | `/:id/retry`        | 手动继续未完成或失败的归档                                                                                     |
| DELETE | `/:id`              | 原子清理非活跃主页任务及其全部批次记录，保留作品、媒体和分组                                                   |
| GET    | `/:id/results.csv`  | 导出当前作品列表与逐项结果，沿用 CSV 公式转义                                                                  |

归档批次响应增加可选 `ownerProfileId`、`ownerPart`，仅由服务端设置，表格创建请求不能伪造归属。

### 第一轮故障识别及刷新恢复

用户反馈普通浏览器未登录时可以显示视频，而程序打开的独立浏览器只显示主页资料，作品区域提示“出错了”。本机隔离复现中，作品列表接口返回 HTTP 200、响应体 0 字节，不能把它解释为必须登录或账号没有作品。

当轮已做有界对照：放行媒体、取消应用请求拦截、换用本机 Chrome、普通代理连接、允许 Service Worker、临时独立浏览器配置目录、先访问首页初始化访客会话，均未在新会话中读到作品。当时尚未定位到单一根因，也未改动系统代理或加入浏览器兼容参数；未把失败归结为用户必须登录，未读取普通浏览器的 Cookie。

本轮修正的是故障识别及恢复：

- 区分列表空响应、非 JSON、HTTP 失败、网络失败与页面实际登录/验证提示；空响应明确说明可手动刷新，不自动反复刷新。
- 页面正常刷新/跳转时保留已发现链接，等待新的页面上下文，避免提前关闭浏览器。
- 刷新会清空本轮分页证明；旧页面迟到响应被忽略，已有链接保留，完整性重新验证。
- 任务结束时释放响应、请求失败及导航监听器；不修改媒体保留和删除规则。

当轮相关 API、调度、浏览器网络、读取及解析的 8 个测试文件共 70 项通过；两个受影响源文件定向覆盖率 94.20%。这些结果证明该轮恢复逻辑，**不代表当时真实主页作品已经获取成功**。后续用户确认普通浏览器无痕窗口也能正常显示视频，因此继续检查交互浏览器启动差异。
