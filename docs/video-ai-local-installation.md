## 为什么原客户端没有均衡与极致

原客户端内置目录和已发布能力包为 1.0.0，只提供 OpenCV 与 Big-LaMa。此前 S07 的 1.1.0 是关闭引擎的未签名审阅材料，不能安装。单独复制源码或重新打包旧能力目录，都不会补齐两套引擎。

本次用户要求继续完成可安装交付，并提供现有能力包签名私钥路径。已用同一受信密钥生成新的本地签名版本，更新源码内置目录中的两项能力：

| 视频去字幕基础包    | `1.1.0-py312-cpu1`   | 新 Worker、时序调度与资源验证辅助脚本；原 OCR、OpenCV、LaMa         |
| 视频去字幕 GPU 加速 | `1.1.0-py312-cu1241` | STTN、ProPainter 固定源码与权重、完整 CUDA 依赖，显式启用两套适配器 |

其他 10 项能力及受信公钥保持原样。旧签名归档、旧安装目录和用户业务数据不修改。新包尚未上传 GitHub，因此本轮使用离线导入，不能依赖发布页在线更新。

## 使用步骤

1. 使用包含本次修改的源码自行制作并安装新客户端；公开命令仍为 `pnpm desktop:make`。本次没有自动制作安装包。
2. 打开 **设置 → 能力管理**，确认基础包和 GPU 扩展显示 1.1.0 或“待更新”。如果仍只看到 1.0.0，请确认安装了新构建并完全退出旧客户端 / 托盘后重新打开。
3. 按下方分卷方式先更新基础包、再更新 GPU 扩展。
4. 重新打开“视频去字幕”。页面根据真实 Worker 健康结果启用均衡 / 极致；不可用时显示各自原因及能力更新入口，不再只显示灰色按钮。

只更新基础包不包含两套模型，必须同时更新 GPU 扩展。安装失败会保留旧 current，不要手动覆盖版本目录或关闭签名检查。

## 长任务在约五分钟后中断的修复

2026-11-06 的桌面任务在 705/872 帧、80.85% 时显示失败：任务创建于 13:25:04 UTC，失败记录更新于 13:30:11 UTC。只读核验发现 Worker 未退出，随后进度文件达到 872/872，并生成了输出。这是主程序 HTTP 请求提前断开，不是能力未安装或模型处理到该帧必然失败。

原 Worker 传输只设置了任务级 AbortController，但 Node fetch 仍有独立的 300 秒响应头等待限制。推理接口完成后才返回响应头，较慢的处理因此先被默认网络超时打断。

修复在每次 Worker 请求中使用独立 dispatcher，取消与任务时限冲突的响应头 / 响应体空闲超时，仍由调用方的完整请求时限与取消信号约束；请求结束销毁 dispatcher，不修改全局网络、代理或外部下载设置。响应体读取中的超时和退出中断也不再误报为不兼容 JSON。视频连接失败提示改为检查运行诊断，不再一概要求重新安装能力。

回归入口：`apps/api/src/__tests__/worker-http-deadline.test.ts`。使用真实 loopback HTTP 对照默认传输的响应头 / 响应体超时，检查配置时限、外部中断和连接释放；另有隔离 API 的 310 秒延迟请求对照，证据放在 `.package/video-ai-midprocess-fix-20261106/`。延迟 Worker 是传输测试替身，不属于真实模型画质验收。

本次只修改主程序，无需重签或重新安装 1.1.0 视频能力包。使用新源码自行打包、完全退出旧客户端后更新，再重新提交失败视频；既有失败记录和用户业务数据未被改写，也不将失败后迟到的文件自动标记为成功。

## 独立问题：共享 Python 缓存与整包快照

额外尝试“导出包含共享运行时的完整能力快照”时，严格校验发现共享 Python 运行后有 166 个已签名字节码缓存发生变化；原始 `.py`、视频基础包与 GPU 扩展的全部签名文件均未变化。该行为与运行时缓存重编译有关，不是两套模型缺文件。快照导出明确失败，未跳过校验或交付半成品；失败文件已移到 `failed-export/`，不在离线导入目录中。

该问题登记为 VSEQ-B04。2026-11-07 已修复主程序导出逻辑：检测到共享 Python 或业务包的已签名字节码缓存变化时，从签名清单指定的原始归档下载并校验，临时提取对应缓存用于导出；每个导出文件仍严格核对大小和摘要。已声明分卷内容时，仅下载包含所需缓存的归档，不下载无关模型和 CUDA 分卷。导出结束、失败或取消后清理临时文件，不覆盖已安装文件、不改签名包、不忽略缓存摘要。旧安装未保留原始归档，因此该恢复步骤需要联网，Python 3.12 原始包约 21 MB，声音克隆主归档约 402 MB；无网络时显示具体原因并保留目标旧文件。源码和模型变更仍拒绝导出。桌面端及页面同时保留实际错误信息。上面五个原始签名归档及常规离线安装不受影响。更新主程序后由用户验证实际桌面导出。
