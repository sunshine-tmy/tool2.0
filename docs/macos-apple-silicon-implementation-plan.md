# macOS Apple Silicon 全功能适配：执行计划

> 文档版本：1.0，2026-11-09。代码核查基线：`78e714a486f6372b08af65c90f066682b3108dbb`。
> 编写时工作区干净；本次仅编写实施计划，没有实施 Mac 适配，没有执行模型、Mac 构建或安装验收。
> 面向后续在 Apple Silicon Mac 上使用 GPT-6 Luna「极高」目标模式执行。模型设置不改变本文件的验收要求。
> 本文件是本轮适配的执行依据；[旧 Mac 内部构建指南](macos-apple-silicon-build.md)仅供理解旧入口，不能用其中的旧范围代替本轮目标。

## 1. 完成目标与执行纪律

### 1.1 最终目标

在 Apple M1、16 GB、macOS Sequoia 15.6.1 上安装“电商工具箱”，安装目标机器无需预装 Node、Python、pnpm、Homebrew、Xcode 或 Rosetta。完成必要的 Mac 原生能力安装后，当前 13 个模块及其已有子功能全部可用，包括 STTN、ProPainter、本地音色克隆和归档视频编辑。

- 目标架构：`darwin-arm64`，不针对 M1/M2/M3 等芯片名称设置白名单。
- 拟定最低系统：macOS 14。实际要求取 Electron、Python、全部原生依赖的最高最低版本；不得只修改 `Info.plist` 宣称兼容。
- 16 GB 是本轮重型功能验收基线。8 GB 不承诺全部重型任务；高分辨率和任务规模遵守已有业务限制。
- 先满足个人内部使用，交付 ad-hoc 签名的 arm64 DMG。不接入 Mac App Store，不接入 Mac 自动更新，不新增公开发行流程。
- Windows 继续正常使用；不更换技术栈，不重写业务队列，不重新设计 UI，不新增业务模块。
- 图像 AI 首轮以 CPU 跑通全部功能；克隆保留 CPU，并验证可用的 MPS；STTN、ProPainter 逐引擎验证 MPS、必要的等效混合执行或显式 CPU 执行。
- 保留相同算法、输入几何、区间和框选含义，不追求跨设备逐字节相同的模型输出，不承诺相同速度。
- ProPainter 继续限于此前已确认的非商用使用范围，不能因“个人安装”删除许可证和使用限制。

“全部功能”不等于任意视频都可处理，也不包括突破第三方网站的登录、验证码、地区和作品播放限制；完整版本必须证明原有合法输入范围内的真实业务闭环。

### 1.2 本轮必须修正的执行顺序

原方案把能力制作 M03 放在正式 Worker 适配 M04 之前，可能把尚未适配的脚本签进包；M01 的完整视频验证又必须先有原生解码、编码与合成工具。保留原阶段编号，将必要的媒体依赖准备提前，顺序明确为：

```text
M00 基线
  → M09-A Mac 开发与验证环境准备（不制作 DMG）
  → M02-01 原生 FFmpeg 候选资源（仅满足验证依赖，不签包）
  → M01 隔离模型可行性验证
  → M02-02 完整媒体业务链路验证
  → M04 正式 Worker / 契约 / 资源管理
  → M03 Mac 原生能力包制作与安装闭环
  → M05 全模块业务回归
  → M06 桌面生命周期
  → M07 输入与局域网
  → M08 业务数据跨平台迁移
  → M09-B 内部安装包及干净设备验收
  → 最终逐项完成审计
```

允许在 M01 中制作未签名的验证用 Python、wheelhouse、模型资源和临时推理适配器；M02-01 也只提供验证所需的原生工具。这些都不等于发布能力包。未通过 M01，不制作对外使用的完整能力目录，不开放正式高级档位，不提前批量推进后续阶段。

### 1.3 目标模式的工作规则

1. 一次只执行一个下文的原子任务。先检查工作区，再读实现与测试，再修改，再定向验证，再更新台账。
2. 从最新实际代码出发。若 HEAD 与本文基线不同，先比较相关实现并登记漂移，不能回退用户的新代码。
3. 不自动提交、推送、发布、创建 Release、上传模型或签名材料。不删除旧安装包、旧能力包和用户数据。
4. 不向对话、日志和报告读取或输出 `.env`、Cookie、令牌和私钥内容；只检查必需字段是否存在。需要签名时由用户在 Mac 上指定私钥文件路径，由既有签名程序读取使用，不通过模型上下文传递密钥。
5. 不使用 `any`、关闭检查、降低门槛、删除失败测试、扩大忽略范围来“完成”任务。
6. 无需反复询问已明确的实现选择。遇到真实模型质量、签名密钥、第三方登录等必须由用户提供的信息时，集中提问并记录阻塞，不伪造答案。
7. 不在一项任务中同时改目录、Schema、队列和视觉样式。平台逻辑放入小型适配器，不能创建第二套 Mac 业务实现。
8. 已安装 generation、已发布 manifest、受信公钥、Windows 依赖锁和模型摘要不可原地改写。新逻辑通过新构建、新版本和原有安装流程交付。
9. 不自动执行 `pnpm desktop:make`。M09-B 准备好检查清单后，由用户确认本轮可打包或自行执行；本计划不撤销此前“不自动制作安装包”的要求。
10. 截图、真实外部平台操作和画质人工验收按用户安排执行；不要把未截图、未检查画质的状态记为已通过。

### 1.4 持续执行与暂停条件

- 当前任务完成且前置条件成立，继续下一项，不以“是否继续”结束每一项工作。
- 失败先区分：代码缺陷、缺少资源、外部服务、人工待验、环境不具备。保留最小复现与实际错误。
- 同一报错在没有新假设或新证据时不得反复安装、下载和重跑重型任务。两次相同失败后先定位原因，记录可验证的下一步。
- 真实 Mac 不可访问、缺签名私钥、缺合法素材或必须人工确认画质时，对应项标为阻塞；不得用 Mock 验证代替。
- 停止当前任务的强制条件：出现非预期数据删除、历史记录打不开、取消后提交成功、签名校验绕过、卸载影响其他能力、非本应用进程被杀、必须改变既有输入限制或非商用约束。
- 单个任务阻塞时，只有下文明确没有依赖它的文档/诊断准备可继续。不能绕开 M01 把后续完整版本标为可发布。

## 2. 开始实施前需要收集的东西

### 2.1 从 Windows 拉取什么

- 由用户先将所需源码与本文提交、推送，再在 Mac 拉取同一分支。本文编写不包含这一步。
- 不复制 Windows `node_modules`、虚拟环境、`.runtime`、`.env`、已安装 `components` 或整棵 `storage` 来启动 Mac。
- 公共模型权重可以由用户离线提供，但必须与项目固定来源和摘要匹配。不能把权重可复用理解为 Windows 能力包可导入 Mac。
- 准备现有模块备份功能导出的业务数据包用于 M08；第一次验证使用合成数据，不使用唯一业务数据副本。
- 正式签名时准备 Mac 可访问的能力包私钥路径；不把旧 Windows 绝对路径写入新脚本。

### 2.2 Mac 构建机与安装目标机的区别

构建/验证机允许具备 Xcode Command Line Tools、Node 24、pnpm 11.7.0、Git、固定版本 uv、受管 Python 3.12 和开发测试依赖。安装目标机不得依赖这些开发环境。

第一步只执行以下检查，不提前制作安装包：

```sh
git status --short
git rev-parse HEAD
uname -m
sw_vers
sysctl -n hw.memsize
sysctl -in sysctl.proc_translated 2>/dev/null || true
node -p 'process.platform + "-" + process.arch + " " + process.version'
pnpm --version
xcode-select -p
```

预期：`uname -m` 为 `arm64`，Node 为 `darwin-arm64` / 24.x，pnpm 为仓库规定版本。`sysctl.proc_translated` 为 1 表示 Rosetta，先纠正终端和工具链；不存在该项并不单独表示失败。不要把系统自带 Python 当作受管 Python。

### 2.3 验证工作区

使用忽略目录 `.package/macos-validation/<run-id>/`，run-id 使用不重复的 UTC 时间加随机后缀；所有验证输出新建目录，拒绝覆盖已有结果。

建议布局：

```text
.package/macos-validation/<run-id>/
  host.json
  environments.json
  cases.json
  reports/
  logs/
  media/
  storage/
  temp/
```

大模型和下载缓存可在 `.package/macos-assets/` 共享，但验证只读引用，不能修改模型。每次运行报告记录其摘要，不必为每个测试复制全部模型。不要把私钥、Cookie、真实业务内容写入报告或 Git。

验证环境显式设置独立的数据/模型/缓存/临时目录，清除继承的 Python 路径覆盖和 Worker URL。`HF_HUB_OFFLINE` 等参数只是辅助，真实离线验收还要验证外部连接被禁止。需要本地 API 时允许回环通信，不阻断自身 Worker 协议。

开始大型下载、解包或推理前做空间预算：现有缓存 + 待下载资源 + wheelhouse + 三类验证环境 + 安装中间副本 + 新旧 generation + 输入/逐帧中间结果/成品 + 恢复点，并保留明确的额外余量。数字来自实际清单和样本属性，不把 Windows 包大小或“剩余 30 GB”直接当作足够的结论。缺少大小信息先补清单，不让解包到一半才报告磁盘不足。

M01 所有重型用例串行执行。先短片，再代表长片；先单引擎，再资源竞争。内存压力达到预检确定的终止条件、进程被系统杀死或持续失去响应时，保存诊断并停止本项，不无限重试，也不提高 MPS 内存上限来掩盖不足。

## 4. 固定的设计选择

### 4.1 平台与能力包

1. Mac 最终目录恰好包含以下 10 个目标能力 ID：`python-312`、`ffmpeg`、`edge-tts`、`chatterbox`、`image-ai`、`xhs-browser`、`xhs-archive`、`xhs-translation`、`douyin-archive`、`video-ai`。目录完整不代表每项真实任务已通过。
2. Mac 不提供 `python-311`、`chatterbox-cuda`、`video-ai-cuda`；目录生成器、包生成器、manifest 校验和 UI 都要一致拒绝无意义的 Mac CUDA 包。
3. Mac 的 `video-ai` 包包含基础修复、OCR、STTN、ProPainter 源码/权重及依赖；CPU/MPS 使用同一 Mac 原生环境，不新增 `video-ai-metal` 平行包。
4. Mac 的 `chatterbox` 包承载 CPU 与验证通过的 MPS；图片 AI 首轮保留 CPU，未测模型不开放 GPU。
5. 新平台资源命名和下载 URL 必须包含平台隔离。由构建器在 Mac 分支生成 `*-darwin-arm64` 资产后缀（主包、分卷、manifest、SBOM 一致）；Windows 文件名与 URL 保持现状。
6. Mac definition 为新文件或准备器生成的派生定义，不原地修改已发布 Windows 版本。其版本基于实施时实际版本递增并固定，不能假定本文中的旧版本是最新。
7. Mac 目录用经过核实的资源生成。缺线上 feed 时先完成原始归档离线安装；Mac 在线安装和远端摘要验证保持待验，不能虚构下载地址或上传结果。

### 4.2 依赖和最低版本

- 保留 Python 3.12，能力独立 venv，不引入第二个 Python 主版本。
- 在 `tooling/components/macos/` 建立平台依赖输入与可审计锁；公开入口仍是 `scripts/lock-macos-component-dependencies.mjs`。
- Mac Torch 起始版本固定为 `2.6.0`、TorchVision `0.21.0`、TorchAudio `2.6.0`，不使用 CUDA/Windows `+cpu` wheel。沿用现有其他明确固定版本，不能顺手全量升级。
- 补齐视频依赖、einops、SciPy 等完整传递闭包。核验 requirements marker、wheel 平台、Python ABI、最低 macOS、动态库和安装后 `pip check`。
- 所有用户侧安装都使用离线 wheel，不允许 pip 回落源码编译。确需编译的 wheel 在 Mac 构建机制作并登记源码、工具链、命令、产物 SHA-256。
- 锁生成须固定 uv 版本和有效参数。不直接把现有 `--torch-backend cpu` 当成 MPS 可用性的证明。
- M01 确认后，将可复现的 Mac 输入、哈希锁和非敏感 provenance 纳入版本管理；大 wheelhouse 仍在忽略目录。迁移准备器默认路径并保留显式 `--lock` 覆盖；不只保存到 `.package` 导致重新克隆不能复现。
- 核查系统基线时扫描目标二进制 Mach-O load commands 和 wheel tag。若有依赖要求高于 macOS 14，先登记候选降级的兼容性或提高最低版本的影响，不能静默缩小用户要求的范围。

### 4.3 推理设备、健康接口与兼容

- 配音 `device` 枚举扩展为 `cpu | cuda | mps`；旧请求缺省值保持旧语义，Windows 默认行为保持原状。
- Worker 健康结果增加可选 `mpsAvailable`、`mpsUnavailableReason`、`supportedDevices`。已有字段、业务 API URL 和错误码保持兼容。
- 视频每个现有档位增加可选 `supportedDevices` 与 `executionMode`，后者为 `cpu | cuda | mps | hybrid`；`reason` 继续解释不可用原因。不因平台不同改掉档位 ID。
- `supportedDevices` 表示已验证的模型/后端组合，不能等同于 Torch 枚举出设备；未带新字段的旧 Worker 按旧 CPU/CUDA 规则解释。
- MPS 自检失败不伪装“未安装”。区分安装缺失、依赖损坏、设备不支持、引擎未验证和内存不足。
- 保持现有 Worker 协议版本、已发布 Windows `sequence-support` 和 bundle 解释方式。新增 Mac 资源描述若需要扩展，只增加有版本定义且向后兼容的字段；不能全局改 `sequenceRuntime` 让旧 Windows 包失效，也不能复用 Windows 资源声明绕过平台判断。
- 新任务按实际支持设备选择。导入的历史 CUDA 记录保留原值；再生成表单选择当前支持设备，不批量重写历史记录。
- 显式选择 MPS 后失败，默认终止该任务并提供原因；不得静默换算法/换 CPU。若 M01 证明某些子步骤必须在 CPU 等效执行，按固定混合配置运行并明确显示 `hybrid`。
- 不默认全局设置 `PYTORCH_ENABLE_MPS_FALLBACK=1` 掩盖算子问题。不把 CUDA 版本字符串检查替换成“任意 Torch 都接受”。

### 4.4 模型资源准入

- 新增 Mac 专用、API 进程内的 FIFO 重型推理资源协调器，放在 `apps/api/src/core/workers/`。Windows 默认不启用，不合并各业务队列或仓储。
- 图片推理、音色克隆、视频 OCR/修复和显式模型深检获得同一个重型 lease 后才加载模型。普通列表、轻量健康检查、文件下载与音频播放不占该 lease。
- lease 在异常、取消和正常完成的 `finally` 释放；等待中的取消立即移除等待者。发布成功终态仍服从各领域的既有持久化顺序。
- 获得下一类模型的 lease 前，先请求上一空闲 Worker 卸载并确认，无需删除权重；不得卸载仍在处理任务的模型。卸载失败不得继续并行加载重型模型。
- Mac 默认不 eager-load 多类重型模型；已有“常驻”偏好在资源协调约束下展示为可被回收，不能悄悄修改 Windows 或用户永久数据。
- 新的等待说明复用现有阶段文案，不更改数据库状态枚举。重启仍按现有规则处理中断任务，不自动重新生成。
- 统一内存不等于 CUDA 显存。预算来自 M01 实测峰值和系统内存压力；不得直接套用 `cuda.mem_get_info()`、清零水位或绕过系统限制。

### 7.3 阶段台账

```text

```

大日志、媒体、私钥和模型不提交；Git 只保存计划、状态摘要、测试代码和去敏的可复现报告索引。源码、依赖锁或资源定义变动后，对应证据失效，必须重跑受影响项目；不能复制旧“全部通过”到新提交。

## 8. 最终完成审计与交付

### 8.1 逐项审计

最终以本文件每个 M 任务、第 6 节每个用例和以下交付清单反查证据，而不是只看台账是否全打勾：

1. 十类 Mac 能力与实际资源齐全、可信、原生，可离线安装和导出再导入。
2. 四档视频去字幕及本地克隆在 M1 16 GB 的约定范围可完成；算法、分辨率、原音轨和数据保留不缩水。
3. 13 模块及归档编辑/备份/桌面/局域网全部真实闭环；人工画质与听感已确认。
4. 无开发环境安装、覆盖、移动应用、重装和重启复用均通过。
5. Windows 受影响的契约/单测与 Windows 原生/安装结果有证据；只有 Mac 时保留对应待验。
6. macOS 14 与至少一台后续 M 系列设备有真实验收；没有就明确预计兼容，不称全范围完成。
7. 未选模块、已有用户数据、旧签名资源、现有权限和非商用限制全部保持。

若缺设备、签名、远端源或人工验收，允许交付“代码已适配、待某项验证”的阶段成果，但整个目标保持未完成。不能把成功标准缩成“DMG 能打开”。
