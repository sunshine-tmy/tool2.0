# B04：源码/编译态根目录一致性与旧数据保护

日期：2026-10-22。任务为独立缺陷修复，不包含 R02-B 目录搬迁；R00/R01/R02-A 的未提交修改均保留。

## 本次完成与改动范围

- 新增应用侧 `backend/src/project-root.ts`：利用 `src` 与 `dist` 层级一致的锚点定位项目根，不读取 `.git`，不依赖 cwd，也不由公共包位置反推应用路径。
- 后端路径 façade 使用该锚点；源码默认位置不变，编译态不再错误地指向项目父目录。
- `runtime/default-layout.ts` 在默认编译态配置读取前检测旧根的 `.env`、storage、runtime、models 标记（包含符号链接）。发现标记即拒绝继续，错误为 `LEGACY_RUNTIME_ROOT_DETECTED`；权限错误不当作路径不存在。
- 新增显式、仅从进程环境读取的 `TOOLBOX_LEGACY_DATA_ROOT`。必须为已有绝对目录：config/storage/runtime/models 复用所选根，scripts/frontend 等只读资源使用当前项目。
- 显式 `options.layout` 仍具有最高优先级，桌面受管布局不受新选项或默认根检测影响。没有自动选择旧目录、自动迁移或修改数据。
- README 增加提示的处理方式；`.env` 文件本身未修改，新选项不能通过 `.env` 设置，以免发生读取根的递归依赖。

只读核查先仅检查目录/已知文件是否存在，再调用编译配置解析并仅输出路径字段，没有打开业务数据库、输出令牌或私钥。
本机有效路径为项目内的 configRoot、storage、storage/toolbox.db、runtime 和 models 默认位置；项目父目录未发现上述旧路径标记。
此结果只代表本机，其他电脑存在旧标记时仍按拒绝启动/显式确认处理。

## 保持不变的契约

源码已有默认数据位置、环境变量优先于选定 `.env` 再使用默认值的规则不变；既有 STORAGE_ROOT、DATABASE_PATH 等显式覆盖项不变。
选定旧数据根时，相对路径仍以该 configRoot 解析；不会复制、转换或重命名 SQLite、媒体、模型或能力包。
API、页面、workspace 包名、数据库 Schema、保留/删除/恢复规则、桌面数据根及分发资源名称不变。
本次有意修复的是编译态错误的默认根，并通过旧路径保护防止静默切换；不是声称编译态错误行为也保持不变。
