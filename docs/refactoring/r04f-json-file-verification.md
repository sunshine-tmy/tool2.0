## 范围与证明

Chatterbox timing 与 Edge-TTS 元数据的 writeJsonAtomic 使用同样的 mkdir、pid/时间戳临时名、2 空格 JSON、UTF-8 写入及 rename。两者一个为 async 函数，一个返回立即执行的 async Promise；提取前在独立 VM 用受控 fsp/时钟记录成功和 mkdir/writeFile/rename 三类故障，I/O 参数序列及错误对象传播相同。比较跨 VM 的序列化观测，不将不同 realm 的对象原型差异误判为业务差异。

原样采用 async 版本为 speech/shared/json-file 的唯一实现，两个调用方直接导入，不保留无消费者包装。除 import/原 JSON 辅助函数外，两份队列/仓储声明与固定基线 AST 完全相同。没有改变排队、事务、重启恢复或最终状态发布时机。

保留普通临时 rename 策略：无新增 fsync、backup、随机名或失败清理，不把它改成持久文件网关或备份替换。JSON 格式、无额外末尾换行、临时名、错误传播及原失败残留规则保持，不触碰用户存储。
