## 改动范围

- 迁移前端源码、配置、公共图标和测试；同步 workspace、lockfile importer、别名、CI、CODEOWNERS、预算、清理目标和操作文档。
- API 的默认源码前端产物路径映射为 `apps/web/dist`；显式覆盖仍优先，通用运行时包的历史默认值不变。
- 桌面分发仍映射为 `resources/frontend`，API 分发名称仍为 `resources/backend`。
- 桌面开发模式保持原来“源码根目录”的相对语义，仅将目录名等价改为 `apps/web`；没有混入 B05 修复。
- 初始化及诊断通过 `apps/web/package.json` 定位 Vite。包名和根命令保持不变。
- 新增 Node 专用的 `apps/web/tooling/dev-config.ts`，不进入浏览器源码。
  `.env` 解析与整数校验从 API 等效提取至 `@toolbox/runtime-core`，API 和 Vite 共用，导入时不读文件、不创建目录。

## 保持不变的契约及配置边界

- workspace 包名仍为 `frontend`、`backend`，既有启动、停止、数据库、构建、桌面命令名称不变。
- 页面路由、懒加载入口、273 个 API/健康检查方法与路径、错误码和业务字段不变。
- 根目录仍为 Vite `envDir`；VITE 模式文件、环境变量优先级、开发 host/port、strictPort、preview 代理和 `xfwd` 保持原设置。
- API 代理显式 `VITE_API_PROXY_TARGET` 优先；未指定时仍按进程 `API_PORT`、所选 `.env`、3100 的顺序解析。
  空进程值仍覆盖文件值后使用默认端口；范围仍为 1–65535，保留原 `Number` 转换及错误文本。
- API 的端口读取仍只使用所选 `.env`，不因 Vite 支持模式文件而改用 `.env.local` 中的 API_PORT。
- `TOOLBOX_LEGACY_DATA_ROOT` 显式选择配置目录的规则保留，Vite 根目录和只读资源目录不随该选项改变。
- Vite 不再顺带执行与代理无关的 API 业务校验。API 自身仍执行原有全部校验，例如 LAN 模式必须配置 ADMIN_PIN。
  此职责调整在实施前说明，并有后端回归断言；没有放松后端安全规则。
- 数据库、存储、模型、能力包、Worker、数据保留和删除规则不变；固定签名清单及 Python 锁文件摘要通过。
- lockfile 只改必要的 importer/链接及前端 Node 构建工具对已有 runtime-core 的工作区引用；依赖图和 snapshots 与固定基线字节一致。

## R02-C-Q01：迁移期间差异覆盖率识别校正

初次门禁为 54668/60999（89.62%）：原检查器使用 `--no-renames`，又把未提交目标文件全行纳入，
将整棵机械迁移的旧源码误视为新增。问题与调整先向用户说明，没有降低 90% 门槛或增加忽略规则。

现在使用 Git 原生 rename/hunk 识别：

- PR 使用固定比较基线与 HEAD 的实际提交差异。
- worktree 使用专用临时 Git 索引识别未跟踪的目标，真实索引不暂存、不改写；比较基线仍固定。
- 纯移动没有新增可执行行，但仍要求应统计的生产文件存在 LCOV。
- 移动中的真实修改逐行统计；新增文件、原文件仍存在的复制文件仍全量统计。
- 新增 4 项真实临时 Git 仓库测试，覆盖上述情况、未覆盖修改、已暂存用户文件、提交态/工作态区别以及失败时真实索引不变。
  测试提交只发生在合成临时仓库，未提交项目代码；临时路径经校验后清理。

校正后的固定基线 worktree 差异覆盖率为 **115/116（99.14%）**。
未覆盖的一行为现有诊断 CLI 的依赖定位改动；由命令/启动链路另行验证，不通过扩大排除消除它。
该统计与 R02-B 当时将迁移整文件计入的 92.95% 不可直接比较，历史记录保持原样。
