# 归档视频配乐与图集生成视频

实现基线：`9898fe3`，2026-10-28。开始时工作区干净，局域网二维码已经在该基线内提交。本功能不改签名包、不增加模型或 Python 依赖，不制作安装包。

## 使用入口

1. 左侧原“直播音频库”升级为“音频素材库”，页面、工具 ID 和 API 地址不变。新增“配音素材”“背景音乐”视图，原来的全部音频、分组、播放队列、回收站、裁剪和备份继续可用。
2. 上传或编辑音频时可选用途。旧记录不重写：已有配音引擎来源在配音视图中展示，其他未分类记录仍在全部音频中。用途随备份与恢复保留；原来的分组不自动移动或改名。
3. 打开多媒体归档详情，在视频下点击“编辑配乐”。支持 TikTok、抖音、小红书和实况视频的实际视频媒体。
4. 选择库中音乐或直接上传 MP3、PCM WAV、AAC M4A、FLAC，单文件最大 100 MiB。上传直接加入统一素材库；关闭编辑器不删除已上传素材。相同文件继续按原库规则去重，不静默修改已有素材的用途、文案或分组。
5. 分别调节原声和配乐 0–100% 音量，支持静音、音乐起点、短音乐循环或播完停止，以及最长 5 秒淡入/淡出。原声中讲话与原有音乐整体调节，不进行 AI 人声分离。
6. 点击“试听 15 秒效果”，后台按相同混音参数生成当前指定起点后的最多 15 秒。试听不修改归档，参数改变后需再次生成试听。
7. “保存为最新版本”完成后，详情、单文件下载及 ZIP 使用最新成品。“查看原始视频”“恢复原始视频”始终基于保留的原片；可以保存后继续调整音量、换音乐或重新打开编辑器。
8. 关闭窗口不停止后台任务；重新打开同一媒体会接续当前任务状态。任务可以明确停止，最终文件提交阶段需等待完成。程序重启后中断任务记为失败，不自动重新生成。

## 原片与版本保留

- 每个视频长期保留原片、当前最新成品、编辑参数及当前音乐的独立副本。每次换歌和改音量都从原片重新混音，不在旧混音成品上继续叠加；已保存配乐不依赖音乐库条目继续存在。
- 新文件校验、归档清单、文件索引和任务完成记录提交成功后，才发布成功状态。新成品使用独立文件名，不覆盖正在播放或下载的旧文件。
- 不提供无限成品版本历史。已退休成品和旧配乐在没有播放/下载租约后清理；清理失败的文件留在退休清单中重试，仍计入归档配额。启动时修复该清理队列。原片、当前成品、当前音乐、截帧及其他素材不进入该清理队列。
- 新生成文件、原片和音乐均计入原归档容量。磁盘不足、超过配额、编码失败、取消或数据库提交失败均不替换原有可用视频。原有作品删除、永久归档与音频库回收站规则不变。
- ZIP 是发布成品导出，默认包含最新视频；不会额外导出隐藏原片和配乐快照。需要保留重新编辑能力时，应随应用数据备份整个归档目录及数据库。

## 重新获取与并发

现有归档刷新会替换整个媒体目录，因此本功能增加显式保护：

- 同源刷新保留已编辑成品、原片、配乐和截帧，不把编辑结果当作平台媒体覆盖。
- 平台返回的视频源已改变时，明确拒绝覆盖。用户先“恢复原始视频”，再重新获取，才采用新来源。
- 同一作品同时只允许一个配乐任务。运行中禁止删除和刷新；其他作品的归档可以继续。开始与最终提交均校验媒体摘要和编辑版本，迟到的页面请求返回冲突。
- FFmpeg 的任务状态纳入维护、诊断和能力卸载保护；只终止本服务创建的子进程。浏览器只提交素材 ID、版本和数值设置，不接受本机路径、远程媒体地址或任意 FFmpeg 参数。
- LAN 写操作继续要求管理员会话、精确 Origin 与 CSRF，不扩大访客权限。

## 图集生成配乐视频

图片媒体下提供“图集生成视频”，按归档内原图顺序生成附加视频。每张停留 0.5–30 秒，最多 100 张；支持竖版 720×1280、横版 1280×720、方形 1080×1080，按比例完整放入白色画布，不裁剪原图。

先生成独立无配乐原片，再使用相同混音管线生成成品。原图片及顺序保持不变，新视频加入同一作品，之后按普通视频继续调整配乐。再次从原图生成会新增独立视频，界面明确提示；恢复生成视频的原片不会删除原图。来源图片发生变化时拒绝刷新，保留已有原图及成品，不自动采用新图或重新生成。

本轮不增加多作品批量套用配乐、AI 分轨、转场或视频剪辑时间线。

## 运行时与临时文件

复用已安装 FFmpeg/FFprobe；桌面使用验签后的共享运行时，源码环境可沿用现有 FFmpeg 配置。缺失时显示能力提示，不自动下载能力包。兼容 H.264/HEVC 视频优先复制画面流，只重编码声音；其他视频转为 H.264，视频最长 2 小时。图集生成和片段试听使用 H.264 编码。

试听只保留 MP4，音乐副本、归一化图片与中间原片在试听成功后立即删除。试听文件最长保留 1 小时，最近完成任务元数据最多 200 条；这是本功能新增的临时资源规则，不作用于任何永久素材。客户端关闭或切页后停止轮询并释放请求，不自动停止服务端任务。

## 新增接口

统一前缀 `/api/v1/tools/media-archive`：

- `GET /video-edit-runtime`：已安装媒体运行时可用性。
- `POST /items/:id/media/:mediaId/audio-edits`：保存、试听或恢复；包含摘要、编辑版本、数值设置和可选音乐 ID/版本，图集另含有序图片 ID/摘要与画幅。
- `GET /items/:id/media/:mediaId/audio-edits`：该媒体最近任务，重新打开时恢复活动任务观察。
- `GET /video-edits/:taskId`、`DELETE /video-edits/:taskId`：查询或安全停止。
- `GET /video-edits/:taskId/preview`：临时试听视频，支持 Range。
- `GET /items/:id/media/:mediaId/original`、`.../saved-music`：受控原片和当前配乐快照，支持 Range。

编辑状态是兼容旧记录的可选字段，沿用现有清单与 SQLite 通用实体存储，不增加数据库 Schema 迁移。
